# auto-ledger · 账簿自动登记

这个脚本装在浏览器里，帮你把「网中网会计综合实习平台 V6.3」上已经录好的记账凭证，按会计科目汇总，自动一笔一笔登进平台的 T 型账。

它已经在一批真实数据上跑通过：103 张凭证、417 条分录，汇总成 45 个科目，全部核对一致。

> 仓库与脚本已更名（旧名只覆盖 T 型账，与现在的范围不符，旧地址会自动跳转过来）。**目前可用的是 T 型账这一环**；明细账那一环的规格见 [`docs/specs/0001-detail-ledger-automation.md`](docs/specs/0001-detail-ledger-automation.md)，尚未实现。

## 装之前

浏览器要先装 Tampermonkey（油猴）扩展，装法见[官网](https://www.tampermonkey.net/)。

## 拿脚本

脚本本体在仓库里：[`userscript/auto-ledger.user.js`](userscript/auto-ledger.user.js)。

点开这个文件，鼠标移到代码块上，右上角会冒出一个复制按钮，点一下全文就进剪贴板了，再去油猴里粘贴。页面上不好复制的话，直接下载这个文件也一样。

代码块有两千多行，不用手动拖选。复制到的内容要从第一行 `// ==UserScript==` 开始，到最后一行 `})();` 结束。粘进油猴之后搜一下 `@version`，看到 3.3.1 就对了。

## 装什么

1. 点油猴图标，选「添加新脚本」。
2. 把里面的模板内容全部删掉，粘贴刚复制的脚本。
3. 按 `Ctrl+S` 保存。
4. 确认装对了：油猴图标上会显示一个数字，点开能看到「网中网会计综合实习平台 · 账簿自动登记」，版本是 3.3.1。

粘贴的时候要从第一行 `// ==UserScript==` 开始，到最后一行 `})();` 结束，中间一句都不能少。粘完在编辑器里搜一下 `@version`，看到的是 3.3.1 就对了。

## 怎么跑

1. 正常登录平台，点企业名进实训，进到能看到左侧菜单的界面。
2. 点开左侧的「T 型账」页面。
3. 面板会自己出来，位置在 T 型账那块页面的右上角。

在校内直接打开平台，或者在校外用学校的 WebVPN 打开，两条路都能用，脚本不用改。

第 3 步容易误会：面板不一定在浏览器窗口的右上角。平台的页面是几块拼起来的，面板跟着 T 型账那一块走。找不到就先确认自己有没有点开 T 型账。

面板长这样：

```
凭证登 T 型账                                    收起
年份 [2020]  月份 [1]
[清空 T 型账] [获取教师答案并写入 T 型账]
[获取学生答案并写入 T 型账] [删除本地存储答案]
[停止]
┌──────────────────────────── 日志区 ────────────────────────────┐
│ 就绪                                                          │
└───────────────────────────────────────────────────────────────┘
```

平时只有这些按钮，没有别的开关，也没有复选框。日志区第一行是句提示，开始跑之后会被清掉。真碰到冲突科目的时候，面板会临时多出两个按钮来问你，选完就收了。

点右上角的「收起」可以把面板缩起来，免得挡住下面的表格。

## 面板上的按钮

点一下写入按钮，脚本就直接改平台上的数据，改完不能撤销。动手之前想先看一眼这次会写什么，能看的就是日志区：脚本会先报出打算写几个科目、几行。点下去就是全量，一次写完所有科目。

建议按下面的顺序点，面板日志区开头那行提示写的也是这个顺序。

| 顺序 | 按钮 | 点下去做什么 | 会不会改平台 |
|---|---|---|---|
| ① | 清空 T 型账 | 把这个期间平台上有数据的会计科目清空。点下去先弹一个确认框，你确认了它才开始扫 | 会，不能撤销 |
| ② | 获取教师答案并写入 T 型账 | 取平台上内置的那份标准答案凭证，跟你的账号无关，汇总后写进 T 型账 | 会，不能撤销 |
| ③ | 获取学生答案并写入 T 型账 | 取你自己录的凭证，汇总后写进 T 型账 | 会，不能撤销 |
| ④ | 删除本地存储答案 | 只删这台电脑浏览器里存的凭证数据 | 不会，不碰平台 |

写入的过程中发现不对，可以随时点「停止」，正在提交的那一行会写完，后面的就不写了。脚本会把手头已经发出去的请求收完再停，不会再发新的。

脚本读凭证的时候是几路一起读的（快），但往 T 型账里写、以及清空 T 型账，都是一个科目一个科目来的，不会同时动两个科目。这是故意的，不是没优化：同时动多个科目的时候，平台返回给你的页面会缺内容——表现就是「清完了却剩下一两行」或者「科目没切过去」。以前那个同时动多个科目的版本就是这么坏的，所以现在一律排队走。代价是慢一些：原本能重叠的网络等待，现在变成一个个累加。按真机抓包的实测，单次读取平均约 0.8 秒，而清空一轮光只读读取就有 155 次——四路并发约 48 秒，串行约 194 秒，差两分多钟。这个时间花得值：换来的是不再出现「清完还剩一两行、还得再跑一遍」。

想在写入之前先看看平台上有没有拦路的东西，看日志就行：脚本动了平台之前，会先把平台上的会计科目整个查一遍，报出哪些科目已经有数据、和这次的计划对不对得上。要是发现对不上的，它会停下来问你一句，面板上多出两个按钮，你选「清掉这些科目并继续」还是「跳过它们」。

对不上的科目不再只有「全清重来」一条路了。以前碰到这种情况，你得先点 ①「清空 T 型账」把整个期间清干净再重跑；现在是脚本问你要不要只清掉那几个科目。

想推倒重来，还是点 ①「清空 T 型账」。

「清空 T 型账」扫的是平台上所有的会计科目，不只是你这次用到的那些。所以它清的范围比你想的可能要大。它只清面板上那个年份和月份的数据，别的期间不动。

如果这批 T 型账数据不能随便清，那就别点 ①「清空 T 型账」，只点 ② 看看日志。

## 年份和月份

面板上的年份默认 2020，月份默认 1。这是写死的默认值，脚本不会自己认出来你这次是哪个月的实训任务。你的任务如果不是 2020 年 1 月，一定要手动改，写错了会查到空数据，或者写到别的期间去。

## 凭证数据存在哪

点过「获取教师答案」或「获取学生答案」之后，抓到的凭证就缓存到你这台电脑的浏览器里了，之后再怎么点这两个按钮都直接用缓存，不会重新联网抓。一轮一百多张凭证要跑好几分钟，所以这个省事是有意做的。

有个地方要注意：用缓存的时候，日志不会专门说一句「这次用的是缓存」。你要是觉得按钮点下去很快就跑完了，那多半就是走的缓存，不是出错了。

想重新抓一遍，先点「删除本地存储答案」。

老师那份答案只有一份。换过一次实训任务之后，再点 ②，日志会提醒一句这次取到的数据是上一批任务的，照样能往下跑，想用新的就先点 ④ 重抓。

你自己录的那份答案只存在你的名下，同一台电脑换同学登录，两份不会串。

④「删除本地存储答案」删的是本机浏览器里存的全部凭证数据，老师那份和你自己那份都在内，平台一点不动。可以放心点。

## 出了错怎么办

面板上的日志写得比较细，大部分问题看日志就能定位。

登录失败：平台会弹「密码或用户名错误，请重试」，检查你输的账号密码。

抓到的凭证张数不对劲：多半是平台的分页结构变了。日志会显示每页抓到几张，你对着平台上凭证列表的总数看一眼就知道差在哪。

日志说账目不平：脚本在写之前会自己核对一遍账目平不平。核对的办法是两条：每张凭证自己的借方合计必须等于它的贷方合计；把分录按科目加总，和先加总再按科目归并，两条路算出来的数得一样。有任一条对不上，它就停手不写平台。碰到这个先别急着重跑，多半是平台上的原始数据本身有问题，或者页面结构变了导致解析漏了行。

日志里有「未执行」三个字：脚本还有第三项核对，是拿平台上的官方答案和你自己录的凭证对一遍。你只点了一个写入按钮的时候，本地还没有另一份数据可比，这项就标「未执行」。没做这项检查和这项检查通过了是两回事，日志里会写清是哪种。这项不拦你写入，前面那两项才拦。

日志里有「N 张凭证未审核」：这个不影响写入。凭证有没有审核过跟能不能登进 T 型账没关系，平台自己也不管这个。日志只是提一句。

日志里有「跳过」：已经写过的科目不会重复写，这是正常的。判断算不算写过，看的是凭证号前缀、金额和方向，不看摘要。还有一种是平台上已经有数据、但和这次的计划对不上，脚本会停下问你：清掉那几个科目再写，还是跳过它们。你要是不想让它动那些科目，就选「跳过它们」。

日志里有「平台 N 行 / 计划 M 行」：这是脚本列的冲突科目清单，一行一个科目。N 是平台上现在有几行，M 是这次打算写几行。想清掉它们继续，点「清掉这些科目并继续」；不想动，点「跳过它们」。清单里报出的科目，脚本一个都还没动过。

日志里清空汇总出现「未清干净 N 个」：这几个科目删完还剩了行，脚本会自己换个最新行集再删，最多重来三次；仍然剩的话，汇总里会点名。再点一次「清空 T 型账」通常就清掉了。看到这行不要以为平台清干净了，它是在告诉你还有残留。

日志里清空汇总出现「复核未读到 N 个」：这几个科目删完之后，脚本没读到它们的状态，所以结果谁也不确定，**不能**当成清干净了。多半是平台偶发返回了一种「科目下拉是空的」的页面。脚本碰到科目清单为空会自己重试一次；仍失败就如实报出来。隔一会儿再点一次即可。

日志里有清空项后面标了「重删 N 次后」：说明第一次删没删干净，脚本自己又删了，最后是干净的。正常现象，不用管。

日志里清空项报「响应完整性判据未过」：平台这次返回的页面缺内容（少了行，或者行金额和合计对不上）。脚本**不会**把它当成「本来就没有行」——那样会一行都不删却报告一切正常。它会自己重取几次；仍然缺内容就明确报错，那个科目这一轮算失败。看到这行说明平台这一下返回得不完整，隔一会儿再点一次「清空 T 型账」即可。脚本还会拒绝另一种页面：平台偶发返回「科目下拉是空的」的降级页（页面明显偏小）。这种页不是某个科目的真实状态，脚本不会拿它当「这个科目没有数据」。


日志里有「计划外科目」：平台上有些科目有数据，但这次的计划里根本没有。脚本只把它们列出来给你看，一个都不动。它们可能是别的实训任务留下的。

日志里有「状态未知」：这几个科目的情况脚本没查明白，这一轮就不写它们。没查明白和「平台上没有数据」是两回事，前者可能是有数据的，所以脚本宁可跳过也不往上面叠着写。再跑一遍通常就好了。

面板上报错：常见的原因有三个。日志里说找不到 `entityID`，说明你还没进实训企业。说取不到答案凭证，说明你还没打开过 T 型账页面，或者网络、平台地址变了。说读回来的结果解析不出来，说明页面结构变了。

某个科目没写成：日志会写明是哪个科目、失败原因是什么，也会统计进最后的汇总里。常见原因是平台返回的科目和你要写的对不上，或者那个科目已经有数据但和计划不一致。

日志里有「写后复核读不到」：这个科目的行**可能已经写进去了**，只是脚本没读到，所以既不算成功也不算失败。去平台上这个科目的 T 型账页看一眼确认，再决定要不要重跑。

写到一半停了：平台对每个科目的行数有上限，写不下的会被拒。这种情况平台上会留半截数据，两条路恢复。一是回到面板点「清空 T 型账」重来。二是到那个科目的 T 型账页面上全选，点「删除提交」，再回面板重跑。

每写完一个科目，脚本都会回平台上把刚写进去的数据读出来对一遍，确认写进去的和计划的一致。日志最后那行汇总里，对账一致的数量就是这个结果。
