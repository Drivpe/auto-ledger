# 手工测试清单 v3 —— 面板四按钮版

> **本文档对应 v3 面板形态，与旧版面板（含「演练模式」复选框、「先清空该科目再重写」「只清空，不重写」）不兼容。**
> 如果你看到的面板上还有「演练模式」勾选框、只有一个「开始」按钮，说明装的不是本文对应的版本，本文所有步骤都不适用。
>
> v3 面板长这样：
>
> ```
> 凭证登 T 型账                                    收起
> 年份 [2020]  月份 [1]
> [清空 T 型账] [获取教师答案并写入 T 型账]
> [获取学生答案并写入 T 型账] [删除本地存储答案]
> [停止]
> ┌──────────────────────────── 日志区 ────────────────────────────┐
> │ 就绪                                                          │
> └───────────────────────────────────────────────────────────────┘
> ```
>
> 面板上**没有任何说明文字块、没有警示区、没有复选框**。这是 v3 的规定形态，不是安装出错。

---

## 零、测试前必读

### 0.1 哪些用例会真的改平台数据，且不可恢复

**平台没有事务、没有回滚。** 一旦执行到底，平台上的 T 型账就变了，唯一恢复手段是清空后重跑（清空本身也是破坏性动作）。

**A. 注定会改平台、不可恢复的用例**（执行前必须已确认数据可以随便清改）

| 用例 | 动作 |
|---|---|
| `C1.5`、`C3.1`、`C5.1`、`C5.2`、`C8.1`、`C8.3` | 点「获取教师答案并写入 T 型账」（往平台上插行） |
| `C2.2`、`C2.3`、`C2.4`、`C2.5`、`C7.4` | 点「清空 T 型账」并确认（删掉平台上已有行） |
| `C3.7`、`C7.2` | 写入中途中断，平台上会留下写一半的科目 |
| `C4.1`、`C4.5` | 点「获取学生答案并写入 T 型账」（往平台上插行） |
| `C8.4`、`C8.5` | 连点写入按钮 / 首次跑教师答案写入 |

**B. 点的是写按钮，但设计上应当「零写入」的用例**（只在判据正常时安全；判据失效就会写坏数据，所以同样要先确认数据可以随便改）

| 用例 | 预期 | 失效后果 |
|---|---|---|
| `C3.6` | 平台已等于计划 → 全部跳过、零写入 | 判据失效则**翻倍**写入 |
| `C4.3` | 学生答案为空 → 不写 | 空数据仍写入 |
| `C4.4` | 学生答案与平台已有行不匹配 → 全部跳过 | 教师答案的行被学生答案**覆盖** |

**C. 只动本地、不碰平台的用例**

| 用例 | 动作 |
|---|---|
| `C1.1`、`C1.2`、`C1.3`、`C1.4`、`C2.1`、`C3.2`、`C3.3`、`C3.4`、`C3.5`、`C4.2`、`C5.3`、`C5.4`、`C5.5`、`C7.1`、`C7.3`、`C8.2` | 只读、抓取期间停止、停止后核对、面板重渲染 |
| `C6.1`、`C6.2`、`C6.3`、`C6.4` | 删本地答案缓存（不碰平台） |

> `C2.1` 在弹窗上点的是**取消**，所以归入 C 组。`C3.5` 需要在平台上手工改一个科目的行来构造前置条件，那一步**是你自己动的平台数据**，不在脚本行为之列。

### 0.2 没有演练模式兜底

v3 把「演练模式」删掉了。后果是：

- **不存在「先只看一眼将要写什么、不碰平台」这条路。**
- 面板上四个按钮里，**两个写平台、一个删平台数据**，点下去就开始动。
- 年月的默认值 `2020` / `1` 是**写死的兜底值，不是自动识别**。你的实训不是 2020 年 1 月，就必须先改。

> **开始测试前，先自己确认一句话：这个实训批次里的 T 型账数据可以随便清、随便改，清错了也没人找我。**
> 确认不了就不要执行本文标注「改平台」的用例，其余只读用例照跑。

### 0.3 你需要准备的东西

1. 浏览器已装 Tampermonkey（油猴），本文对应的脚本已装进去并**已保存**。
2. 已登录平台，并且**已经点进某个实训企业**（能看到左侧菜单那个界面）。
3. **先点开左侧「T 型账」页面。**
4. 平台页面是 frameset（整页由多个小框拼成）。**面板出现在「内容框」的右上角，不是浏览器窗口的右上角。** 也就是：面板会跟着 T 型账的内容一起滚动、位置在内容区域里。看不到面板时，先点开 T 型账页再找。

> 术语速查（本文只使用这几个词）：
> **教师答案** = 平台内置的标准答案，与学生账号无关。
> **学生答案** = 当前登录学生自己录入的记账凭证。
> **答案缓存** = 教师答案与学生答案抓到后存在浏览器本地的副本，下次直接用。
> **实训批次** = 登录后实习批次列表里的一行（含「进入实习企业」那个链接）。换批次就是换实训任务。
> **总账科目** = T 型账页最上面那个科目下拉里的科目，本项目里叫「一级科目」。

### 0.4 日志怎么读

- 日志是一行行往下追加的，**不会自动滚到底**，需要自己往下拉。
- 配色：绿色 = 正常完成；黄色 = 警告（继续跑）；红色 = 失败（停手或跳过）。
- 日志文本以你装到的实际脚本为准。本文给出的日志样貌是**「应该出现的关键词」**，不是要求逐字相同。判断用例通过与否，看关键词，不看句式。

### 0.5 测试时手边要开的对照表

测「写入」时，你要能说出**应该写多少个科目、多少行**，否则看不出写对了没有。可以这样拿对照：

- 在平台上打开「记账凭证」列表，数总张数（本项目实测样本是 103 张）。
- 写入完成后，日志自己会报「科目数」与「行数」；把它和平台当时的情况对照。

## 一、准备与冒烟

### C1.1 脚本装好、面板出现

**背景**：这一步只判断「脚本在不在、面板有没有出来」，不碰任何数据。

**前置条件**：Tampermonkey 已装脚本；已登录平台并进入实训企业。

**操作步骤**
1. 点左侧菜单的「T 型账」。
2. 在内容区域的右上角找绿色面板。

**期望结果**
- 面板出现，标题是「凭证登 T 型账」，右侧有「收起」。
- 面板上有：年份输入框（内容 `2020`）、月份输入框（内容 `1`）、四个按钮、一个「停止」按钮（初始为灰、点不动）、一块日志区。
- 日志区第一行是「就绪」之类的初始文字。
- **面板上没有复选框，没有任何⚠警示区。** 有复选框 = 装错版本，停止测试。

**失败时怎么判断**
- 面板完全没出现：先确认是不是没进实训企业（见 `C1.3`），再确认脚本是否保存成功。
- 面板出现了但在浏览器窗口最右上角、盖住了菜单：说明面板挂错框架，记下来，这不是 v3 期望形态。

---

### C1.2 确认面板挂在内容框架里

**背景**：平台是 frameset。面板必须挂在内容框里，否则写操作会把自己的面板冲掉。

**前置条件**：`C1.1` 已通过。

**操作步骤**
1. 在平台上点左侧另一个菜单（例如「科目汇总表」）再点回「T 型账」。
2. 观察面板的位置和内容。

**期望结果**
- 面板始终出现在**内容区域**的右上角内，不覆盖左侧菜单、不覆盖顶部条。
- 来回切菜单后，面板重新出现，日志回到初始状态（这是正常的，不是 bug）。

**失败时怎么判断**
- 面板跑到窗口右上角、盖住菜单 → 宿主框架不对。
- 切回 T 型账后面板再也不出现 → 记录，属异常。

---

### C1.3 未进入实训企业时的表现

**背景**：脚本要靠 URL 上的实训批次编号（`EntityID`）才知道往哪个批次写。没进批次就取不到。

**前置条件**：已登录平台，**停在实习批次列表页**（能看到一行行批次和「进入实习企业」链接），不要点进去。

**操作步骤**
1. 想办法在这一页找到面板（如果这页没有 T 型账入口，就直接跳到步骤 2 的预期判断）。
2. 若面板可见，点任意一个写入按钮。

**期望结果**
- 日志出现红色的「找不到 entityID」一类提示，并提示你先进入实训企业。
- **不出现任何写入、清空动作。**

**失败时怎么判断**
- 日志里没有这条提示，而是继续往下跑 → 记录，属异常。
- 面板在这一页根本不存在 → 属正常（落地页没有面板宿主），本用例记为「不适用」。

---

### C1.4 年月默认值

**背景**：默认 `2020` / `1` 是写死的兜底值。填错年月会查到空数据或查错期间，**而且平台不会报错**。

**前置条件**：已进入实训企业并打开 T 型账页。

**操作步骤**
1. 看一眼年份、月份输入框的内容。
2. 把年份改成 `2020`、月份改成 `1`（若已被改过）。
3. 不改动，先不要点任何按钮。

**期望结果**
- 年份显示 `2020`，月份显示 `1`。
- 这两个框可以手动改。

**失败时怎么判断**
- 两个框是空的 → 与 ADR 规定的「写死默认值」不符，记录。
- 月份能填 `13`、`0` 之类非法值而没有任何提示 → 记录（v3 没有校验，属已知）。

---

### C1.5 运行中按钮互锁与面板收起

**背景**：一次只能跑一个动作。跑的过程中其它按钮应当点不动，避免同时写。

**前置条件**：`C1.1` 已通过；已进入实训企业。

**操作步骤**
1. 点「获取教师答案并写入 T 型账」（这一条只是看按钮状态，日志开始滚动时立刻进行下一步）。
2. 立刻观察其它三个按钮的外观。
3. 点面板标题右侧的「收起」，再点「展开」。

**期望结果**
- 跑起来之后，其它按钮变成灰的、点不动；「停止」按钮变亮可点。
- 「收起」能把面板折叠成只剩标题条，「展开」能恢复。
- 收起/展开**不影响**正在跑的任务（日志继续增长）。

**失败时怎么判断**
- 跑的过程中其它按钮仍是亮的、可以点 → 记录，有重复提交风险。
- 收起面板后日志消失且不再增长 → 记录。

## 二、清空 T 型账

> **本组全部改平台数据，不可恢复。** 且这一组的清空**不过三锁闸门**——凭证抓不到也照样能清。

### C2.1 正常清空：弹窗立刻出现

**背景**：清空只保留一道防线——一次确认弹窗。弹窗**点下去就弹**，脚本**不会先扫描一遍再问你要不要清**，所以弹窗里**不会告诉你将要清掉多少个科目**。

**前置条件**：已进入实训企业；平台上 T 型账里**确实有数据**（可以先在平台 T 型账页翻几个科目确认有行）。

**操作步骤**
1. 点「清空 T 型账」。
2. 观察弹窗出现得快不快。
3. 读弹窗内容。
4. **先点「取消」。**

**期望结果**
- 弹窗**在点击后立刻出现**（不是等了几十秒、扫完 155 个科目才出现）。
- 弹窗里**只有一句确认语，没有科目数量预告**（不会出现「将清空 N 个科目」这种句子）。
- 点「取消」后，日志不再有新行，平台上数据未变。

**失败时怎么判断**
- 弹窗是**等扫描结束后**才出现的 → 与 ADR「点下去就弹、不先扫描」不符，记录。
- 弹窗里写明了将清空多少个科目 → 与 ADR 不符，记录（不算错，但要看实装选择）。
- 点取消后平台上仍有行被删 → **严重**，立即停止测试。

---

### C2.2 清空正常路径（改平台、不可恢复）

**背景**：确认后脚本会自己挨个科目查一遍、凡是已有行的都提交删除。屏幕上你只会看到一个科目下拉，脚本在背后把全部总账科目都走一遍（约 155 个）。

**前置条件**：`C2.1` 已通过；平台上确实有数据。

**操作步骤**
1. 点「清空 T 型账」。
2. 在弹出的确认框上点**确认 / 确定**。
3. 看日志往下滚，等它停。

**期望结果**
- 日志先出现「扫描」或逐科目推进的行，例如带序号的行：`[1/155] 1001 库存现金…`。
- 对**有行的**科目，出现「清空 N → 0 行」一类绿字；对**本来就没有行的**科目，出现「0 行，无需清空」一类灰字。
- 全部结束后出现一条汇总，形如：`✅ 清空完成：N/155 个科目已核实为 0 行`。
- 汇总里的分母应当是 **155**（全部总账科目数），不是归集出的科目数（本项目样本是 45）。

**失败时怎么判断**
- 汇总的分母是 45 而不是 155 → **记下来，这是本文档点名的 ADR 疑问之一**：清空扫的是哪些科目、扫了多少个，从日志里看不出来。
- 日志承诺了清空却有个别科目报红 → 记下科目编码，到平台上手工核对该科目是否真有残留。
- 清空跑了一半就停、没有汇总 → 见 `C2.5`。

---

### C2.3 清空后再写入（重写形态）

**背景**：v3 取消了「先清空该科目再重写」复选框。要重写，就得**先点清空、再点写入**，两步分开做。

**前置条件**：`C2.2` 已通过（平台上刚被清空）。

**操作步骤**
1. 先点「获取教师答案并写入 T 型账」，等它跑完。
2. 记录日志里报出的科目数与行数。
3. 随便挑一个科目，在平台上手工打开它的 T 型账页核对。

**期望结果**
- 因为平台此时是空的，写入**不会**出现「已有数据但不匹配、跳过」的提示，全部科目都走「写入」路径。
- 日志里出现「写入 M 个科目、R 行」一类汇总。
- 手工核对的科目行数与日志一致。

**失败时怎么判断**
- 明明清空过，写入时仍报「平台已有 N 行，与计划不匹配」→ 清空没生效或科目没扫到，记录并回查 `C2.2`。

---

### C2.4 凭证取不到时，清空仍然可用

**背景**：清空是重置动作，**故意不依赖凭证、也不过三锁**。所以哪怕平台抓不到凭证（网络问题、页面变了），清空按钮也必须能用。

**前置条件**：已进入实训企业；想办法让抓取失败（例如断开外网但保持平台页面可点、或在未抓到任何凭证的新会话里直接操作）。

**操作步骤**
1. 先点「获取教师答案并写入 T 型账」，确认它失败（见 `C3.2`）。
2. 再点「清空 T 型账」，在弹窗上点确认。

**期望结果**
- 第一步：日志出现拿不到凭证的红色提示。
- 第二步：**清空照常执行**，不出现「三锁未通过所以不执行」之类的拦截。
- 清空完成后，平台对应科目确实变成空。

**失败时怎么判断**
- 清空被三锁拦住、提示「校验未通过」→ **与 ADR 直接冲突**，记录。

---

### C2.5 清空中途按「停止」

**背景**：清空一个科目要发两次请求（删一次、再查一次复核）。停止只在两次之间生效。

**前置条件**：平台上数据较多；`C2.2` 已跑通过一次。

**操作步骤**
1. 点「清空 T 型账」→ 确认。
2. 日志滚动到中途时，点「停止」。
3. 记录日志最后几行。
4. 到平台上手工翻 3 个科目，看看是清了还是没清。

**期望结果**
- 日志出现「已停止：清空 i/N」一类提示。
- **正在处理的那个科目会走完它自己的「删除 + 复核」两步**，其余科目不动。
- 平台上：已处理过的科目为空，未处理的仍有数据。

**失败时怎么判断**
- 停止后日志仍在继续清科目 → 记录。
- 平台上出现「删了一半」的科目（例如有行但合计为 0）→ 记录，属异常。

---

## 三、获取教师答案并写入 T 型账

> **本组写入平台数据，不可恢复。** 本组是「全量跑」：45 个科目写入 / 155 个科目扫描，**没有单科目小批量试写手段**（ADR 取消了单科目过滤器）。

### C3.1 正常路径：抓教师答案 → 写入

**背景**：教师答案与学生账号无关，是平台内置的标准答案。第一次跑要联网抓 103 张凭证（可能几分钟），之后会从本地缓存直接读。

**前置条件**：已进入实训企业；已打开 T 型账页；**本地没有教师答案缓存**（全新会话或先做 `C6.1`）；平台上相关科目当前为空或与计划一致。

**操作步骤**
1. 确认年月是 `2020` / `1`（或你实训的真实期间）。
2. 点「获取教师答案并写入 T 型账」。
3. 等日志停住，期间不要按停止。

**期望结果**：日志按下述顺序出现这几段（关键词对得上即可）

1. 上下文行：带出实训批次编号，例如 `上下文：entityID=<批次号>`；若还能拿到会话标识，会带 `SXID=<SXID前8位>…`。
2. 抓取阶段：`抓取记账凭证…` → `共 103 张凭证，417 条分录`（张数与分录数按你的实训实际，样本值仅供参考）。
3. 归集阶段：`按一级科目归集…` → `45 个科目`。
4. 三锁：
   - `锁一 逐张凭证平衡：通过`
   - `锁二 归集双向闭合：通过`
   - `锁三 …` 这一行会是「一致」或「未执行」——**第一次跑通常显示「未执行」**，因为本地还没有学生答案缓存，这是正常的，**不阻断**。
   - 一行 `借贷合计 <金额>`。
5. 写入阶段：`回填 T 型账…`，然后逐科目推进的行 `[1/45] 1001 库存现金…`。
6. 每个科目一行读回结果：`✅ 1001 库存现金：读回 9 行，15232.00/7771.00`。
7. 最终汇总：写入的科目数与行数、对账一致的科目数。

**失败时怎么判断**
- 第 1 行就报「找不到 entityID」→ 见 `C1.3`。
- 第 4 步锁一或锁二显示「失败」→ 见 `C3.3` / `C3.4`。
- 有的科目报「已有数据但不匹配、跳过」→ 见 `C3.5`。
- 汇总里的科目数远少于 45 → 回去逐条看被跳过/报红的原因。

---

### C3.2 失败路径：抓不到凭证

**背景**：抓不到凭证时，脚本不该往平台写任何东西。

**前置条件**：已进入实训企业；**本地没有教师答案缓存**；制造抓取失败的条件（断网 / 平台地址变了 / 会话过期）。

**操作步骤**
1. 点「获取教师答案并写入 T 型账」。

**期望结果**
- 日志出现红色提示，形如 `❌ 没抓到答案凭证。`
- **脚本在写入之前就停下**，不会出现任何 `[1/45]` 逐科目写入行，也不会出现任何读回结果行。

**失败时怎么判断**
- 日志报「没抓到」但后面仍在写平台 → **严重**，立即停止测试并记录。
- 抓取过程中单张凭证失败被跳过：日志会出现 `跳过 记N：…` 一类行，只要最终总数对得上，属正常。若总数明显少（例如只有 30 张），属失败。

---

### C3.3 失败路径：锁一不过

**背景**：锁一 = 逐张凭证借贷各自相等。任何一张不平，整轮**整个不写**。

**前置条件**：需要构造一张借贷不平的凭证（例如在平台上把某张凭证删掉一行分录），或者依靠平台本身存在的脏数据。

**操作步骤**
1. 点「获取教师答案并写入 T 型账」。

**期望结果**
- 日志出现 `锁一 逐张凭证平衡：失败`。
- 紧接着一行汇总 `❌ 锁一/锁二未过，已停止，未写平台。`
- 下面列出具体是哪几张凭证不平，例如 `记N 借贷不平：借 X 贷 Y`（列出的条数有上限，超出会省略）。
- **平台上什么都没有变。**

**失败时怎么判断**
- 锁一报失败但平台上出现了 `[1/45]` 写入行 → **严重**，立即停止并记录。
- 三锁都报通过但你知道有一张凭证是不平的 → 记录（抓取可能漏了那张凭证）。

> 这一条**不依赖缓存**：如果你已经存了教师答案缓存，缓存里也是那张不平的凭证，所以照样能测出来。

---

### C3.4 失败路径：锁二不过

**背景**：锁二 = 用两条独立路径算同一个数（逐笔累加原始分录 vs 先归集再累加），四项必须全等。它是「归集规则写对了没有」的守门人。

**前置条件**：这一条**很难人为构造**，通常靠平台脏数据或页面结构变化触发。

**操作步骤**
1. 点「获取教师答案并写入 T 型账」。
2. 若日志显示锁二通过，本条记为「未触发」。

**期望结果**（触发时；未触发则见下方「失败时怎么判断」）
- 日志出现 `锁二 归集双向闭合：失败`，并给出四项数字，例如 `归集不闭合：凭证 X/Y，科目 X'/Y'`。
- 脚本停手，`❌ 锁一/锁二未过，已停止，未写平台。`
- 平台上没有任何变化。

**失败时怎么判断**
- 锁二报失败但平台被写了 → **严重**。
- **若整轮测试中锁二从未失败过** → 记入末章「未覆盖」，不要写成「已验证」。

---

### C3.5 失败路径：平台已有行且与计划不匹配 → 跳过并报出

**背景**：这是本项目最需要肉眼确认的一条。平台某个 T 型账里已经有行，但和本次要写的计划不一致（一般是上一次写入中断留下的残缺数据）。脚本的选择是**不覆盖、跳过、并在日志报出这个科目**。判据是「凭证号前缀 + 金额 + 借/贷方向」，**不看摘要**。

**前置条件**：先做 `C3.1` 完整写入一次；然后在**平台上手工**挑一个科目，把它的 T 型账删掉一行（或手工加一行），造成「有行但不匹配」。

**操作步骤**
1. 记住你动过哪个科目编码。
2. 点「获取教师答案并写入 T 型账」。
3. 日志滚到该科目时，仔细看。

**期望结果**
- 该科目一行**黄色**提示，形如 `⚠ 1002 银行存款：平台有 48 行，但与计划（49 行）不匹配。本轮跳过该科目以免写坏；…`
- 汇总里单独有一段：`⚠ N 个科目平台上已有数据但与计划不匹配，本轮未动：` 后面跟科目编码清单。
- 还有一句解释行，大意是「行数与计划不符，多半是上次写入中断留下的」。
- 你手工动过的那个科目**编码出现在这两个地方**。
- **平台上该科目的行保持你改动后的样子，没有被覆盖、没有被清空。**

**失败时怎么判断**
- 该科目被静默跳过（日志里找不到它的编码）→ 记录（漏报比报错更糟）。
- 该科目被覆盖或者被清空 → **严重**，与 ADR 的「不覆盖、只告警」直接冲突。
- 日志报出的行数与你在平台上看到的行数对不上 → 记录。

---

### C3.6 幂等路径：平台已有行且与计划匹配 → 静默跳过（零写入）

**背景**：平台已经等于计划时，脚本应当一行都不写，**并且不啰嗦**。这一条本身不改平台数据（前提是判据正确）。

**前置条件**：`C3.1` 已完整跑过一次且读回一致，**中间没有任何人动过平台**。

**操作步骤**
1. 再点一次「获取教师答案并写入 T 型账」。
2. 对比两次日志的写入段落。

**期望结果**
- 每个科目一行绿色，形如 `⏭ 1001 库存现金：平台已有 9 行且与计划逐行一致（…），跳过`。
- 汇总显示写入 0 个科目 / 0 行（或等义表述），对账一致 0 或按实现给出「全部跳过」。
- **平台上没有任何变化。**（可用平台页面刷新前后对比行数确认。）

**失败时怎么判断**
- 第二次跑仍然往平台插行 → 判据失效，**会翻倍写坏数据**，立即停止测试并记录。
- 日志把这些科目报成「不匹配、跳过」而不是「一致、跳过」→ 说明你之前跑的写入形态与当前计划不同（典型是旧形态带摘要 vs 新形态纯字号），**这不算 bug**，但要记录当时的形态。

---

### C3.7 失败路径：写入中途某一行失败 → 该科目中止

**背景**：一个科目内部是逐行提交的。某一行重试若干次仍不成，脚本会**放弃这个科目**，继续下一个。

**前置条件**：需要制造写入失败，例如在写入过程中把网络断掉。

**操作步骤**
1. 点「获取教师答案并写入 T 型账」。
2. 在某个科目写到一半时断开网络（或让平台会话失效）。
3. 观察日志，然后恢复网络。

**期望结果**
- 对该行会出现重试提示，形如 `⚠ 第 N 行第 1 次：响应解析得 … 行（期望 …），且 GET 复核未增行，重试`。
- 重试用尽后：`❌ 1002 第 N 行写入失败，中止该科目`。
- 汇总里这个科目计入失败，例如 `❌ 失败 M 个科目`。
- **该科目在平台上留下一半的行。** 这是预期行为，不是 bug。
- 恢复网络后，脚本继续处理后续科目（除非你按了停止）。

**失败时怎么判断**
- 该科目写了一半但日志既没报「中止」也没计入失败（静默略过）→ 记录。
- 该科目失败后，后续所有科目全部不写 → 记录（可能是整轮被中断，与 ADR 的「单科目中止」不符）。
- 处理方式：到平台上打开该科目 T 型账，手工全选 → 删除提交，清空后重跑；或先点「清空 T 型账」再重跑。

---

## 四、获取学生答案并写入 T 型账

> **本组写入平台数据，不可恢复。**

### C4.1 正常路径

**背景**：学生答案 = 当前登录学生自己录的凭证。它与教师答案结构同构，但内容可能不同（学生可能录错或没录全）。这一条会把**学生的那份**写进 T 型账。

**前置条件**：已进入实训企业；本次登录会话里学生已录入若干凭证；平台上相关科目为空或与计划一致。

**操作步骤**
1. 点「获取学生答案并写入 T 型账」。
2. 等日志停住。

**期望结果**
- 日志结构与 `C3.1` 相同：上下文 → 抓取 → 归集 → 三锁 → 写入 → 逐科目读回 → 汇总。
- 抓取张数可能不等于教师答案的张数（学生少录是常态）。**这不是错误。**
- 因为此时本地通常**已经有教师答案缓存**，锁三这一行有机会出现「一致」或「不一致」而不是「未执行」（见 `C5.4`）。
- 写入完成后每科目一行 `✅ 编码 科目名：读回 N 行，X/Y`。

**失败时怎么判断**
- 学生张数为 0 但日志仍报成功写入 → 见 `C4.3`。
- 报「一致」的锁三却同时显示「未执行」 → 记录自相矛盾。

---

### C4.2 失败路径：取不到学生身份标识

**背景**：学生答案的缓存按学生隔离，隔离键优先用学号，取不到时回退会话标识。学号是从页面标题的展示文本里抠出来的，平台没有格式契约。

**前置条件**：能复现「取不到学号」的情形（例如平台标题形态变化、或从非正常入口进入）。

**操作步骤**
1. 点「获取学生答案并写入 T 型账」。
2. 观察是否仍然能抓、能写。

**期望结果**
- 若回退成功：日志照常推进，写入正常完成。**日志不会有「取不到学号，已回退」这类提示**（ADR 未要求提示）。
- 若连回退键也取不到：应出现红色提示并停手，不写平台。

**失败时怎么判断**
- 取不到任何隔离键却仍然抓取并写入 → 记录（缓存会串到别人身上，见末章）。
- 整个流程因为取不到学号而中断 → 记录（属未覆盖的边界）。

---

### C4.3 失败路径：学生答案为空（学生没录凭证）

**背景**：学生一条都没录时，抓取结果为空。脚本不该写任何东西。

**前置条件**：用一个**没有录入任何凭证**的学生账号，或先让平台上的学生凭证列表为空。

**操作步骤**
1. 点「获取学生答案并写入 T 型账」。

**期望结果**
- 日志出现「没抓到学生凭证」一类红色或黄色提示（取决于实装）。
- **不出现任何 `[1/N]` 逐科目写入行、不出现任何读回行。**
- 平台上没有任何变化。

**失败时怎么判断**
- 抓取为 0 但日志仍出现逐科目写入 → **严重**，记录。
- 抓取为 0 但日志直接跳到汇总并报「写入完成」→ 记录。

---

### C4.4 失败路径：学生答案与平台已有数据不匹配 → 跳过报出

**背景**：典型场景是「先写了教师答案，再写学生答案」。两者的凭证号、金额很可能不同，于是学生答案在平台上撞上教师答案留下的行，被判为不匹配。

**前置条件**：`C3.1` 已完整写入（平台上已有教师答案的行）；学生答案确实与教师答案不同。

**操作步骤**
1. 点「获取学生答案并写入 T 型账」。
2. 观察逐科目日志。

**期望结果**
- **大量科目**出现黄色「平台有 N 行，但与计划（M 行）不匹配，本轮跳过该科目以免写坏」。
- 汇总里列出这些科目编码。
- 平台上数据保持不变，**不会被覆盖成学生答案**。

**失败时怎么判断**
- 平台上的教师答案行被学生答案覆盖了 → **严重**，与 ADR「不匹配就跳过不写」直接冲突。
- 一个都没跳过、全部写进去了 → 说明学生答案与教师答案恰好一致，属巧合；此时换一个学生再测本条。

> **这是「两个写入按钮并存，先写谁就以谁为准」的直接体现。** 想换一份答案，必须**先清空**再写，不能靠再点一次另一个按钮覆盖。

---

### C4.5 学生答案写入触发的平台状态变化

**背景**：学生答案写进去之后，平台上那个科目的行来自学生凭证，形态与教师答案不同。这一步只是肉眼确认写入真的落在正确批次上。

**前置条件**：`C4.4` 里至少有一个科目**没有**被跳过（例如某些学生凭证碰巧与教师答案一致，或平台上那些科目本来是空的）。

**操作步骤**
1. 从日志里找一个报 `✅` 写回的科目。
2. 在平台上打开该科目的 T 型账页，核对行数与合计。

**期望结果**
- 平台行数、借贷合计与日志报出的数字一致。
- 年月与面板里填的一致。

**失败时怎么判断**
- 数字对不上 → 记录该科目编码与两组数字。
- 写到了别的年月/别的批次 → **严重**，记录并停止测试。

---

## 五、缓存复用

> **ADR 规定：命中缓存时完全静默——日志连「用本地缓存」都不说。** 这直接决定了本组用例的判断方式：你**不能**从日志里看出缓存有没有命中。

### C5.1 教师答案缓存命中（只能间接判断）

**背景**：第一次抓教师答案要联网抓 103 张凭证，很慢（几分钟）；命中缓存时应当很快开始归集。

**前置条件**：`C3.1` 已完整跑过一次（缓存里已有教师答案）；网络正常。

**操作步骤**
1. 点「获取教师答案并写入 T 型账」。
2. 用秒表或心里数数，比较这次「从点击到日志出现归集阶段」用了多久。

**期望结果**
- 从点击到出现「按一级科目归集…」的时间**明显短于第一次**（第一次是分钟级，命中缓存应当是秒级）。
- 日志里**不会**出现任何「用本地缓存」「读取缓存」之类的字样——**这是 ADR 要求的，不是 bug**。

**失败时怎么判断**
- 耗时和第一次一样长 → 缓存没命中（或缓存写失败），记录并接着做 `C6.x` 验证缓存是否真的存在。
- **重要**：如果你既看不出耗时差别、又勾不到「网络面板」，**这条用例实际上无法判断通过与否**，请记入末章的「需要人工判断」。

---

### C5.2 缓存命中时断网仍可写入

**背景**：缓存的意义就是「抓一次永久用」。所以没有网络时，只要平台页面还能操作（或网络只对抓凭证那一步不可用），写入也应当能跑。

**前置条件**：`C3.1` 已完整跑过一次；平台上相关科目为空。

**操作步骤**
1. 制造「抓不了凭证」的条件。
2. 点「获取教师答案并写入 T 型账」。

**期望结果**
- 脚本**不报「没抓到凭证」**，而是直接进入归集与写入（因为用了本地缓存）。
- 写入正常完成，读回结果正常。

**失败时怎么判断**
- 报「没抓到凭证」并停手 → 缓存没生效，记录。
- 这条用例的结论与 `C3.2` 互为反证：如果一个报「没抓到」、一个不报，说明缓存起作用了。

---

### C5.3 学生答案缓存按学生隔离

**背景**：学生答案缓存按人分开存。换一个学生登录，不该读到上一个学生的缓存。

**前置条件**：学生 A 已跑过「获取学生答案并写入」；再改用学生 B 登录同一浏览器。

**操作步骤**
1. 学生 B 登录，进入实训企业，打开 T 型账页。
2. 点「获取学生答案并写入 T 型账」。
3. 观察抓取阶段的张数。

**期望结果**
- 学生 B 的抓取张数与学生 A 不同（各自录的凭证不同）。
- 日志**不会**给出任何「用了谁谁谁的缓存」提示（正常，缓存静默）。
- 若学生 B 平台的凭证列表为空，应当走 `C4.3` 的空数据路径。

**失败时怎么判断**
- 学生 B 直接得到与学生 A 完全相同的张数、且学生 B 自己没录过凭证 → **缓存串号**，记录（这是本清单最需要警惕的一条）。
- 共享电脑场景（机房）尤其要测：同一台机器换人，缓存是否真的分开。

---

### C5.4 换实训批次后教师答案缓存提示不阻断

**背景**：教师答案缓存记下了取数时的实训批次。与当前批次不符时，脚本**只在日志提示、不阻断**。

**前置条件**：在批次 A 里跑过一次「获取教师答案并写入」；然后退出，进入**另一个实训批次 B**。

**操作步骤**
1. 在批次 B 里打开 T 型账页。
2. 点「获取教师答案并写入 T 型账」。
3. 仔细读日志前几行。

**期望结果**
- 出现一条提示，大意是「缓存来自批次 A，当前批次是 B」之类。
- **提示之后脚本继续跑**（归集、写入照常），不因为批次不符而停手。
- 日志里的上下文行的批次编号是**当前批次 B**。

**失败时怎么判断**
- 批次不符时脚本直接停手 → 与 ADR 直接冲突，记录。
- 批次不符却**完全没有提示** → 记录（缓存会拿 A 的数据写进 B，静默脏数据）。
- 提示里出现的是批次 A、而后续写入却按 A 的年月写 → **严重**，记录。

> **学生答案缓存有没有做批次校验，ADR 没有写。** 如果没做，同一学生在批次 B 里会直接命中批次 A 的学生答案缓存。这一条请结合 `C5.3` 一起观察并记入末章。

---

### C5.5 缓存命中时不产生网络请求（需要开发者工具）

**背景**：这是唯一能「直接」确认缓存命中的办法，但要求会开浏览器开发者工具。

**前置条件**：`C3.1` 已跑过；会按 `F12` 打开开发者工具并切到网络面板。

**操作步骤**
1. 打开开发者工具的网络面板，清空记录。
2. 点「获取教师答案并写入 T 型账」。
3. 抓取阶段结束后，看列表里有没有那 103 张凭证的请求。

**期望结果**
- 列表里**没有**凭证列表页与凭证详情页的请求（只有写入 T 型账的那些请求）。
- 归集与写入照常发生。

**失败时怎么判断**
- 仍然出现 100 多个凭证请求 → 缓存没命中，记录。

> **这条用例的目标读者不是会计专业用户。** ADR 明确说缓存命中要静默，代价就是「用户无从验证缓存是否生效」。请把它当成维护者用的一次性验证，而不是交给同学的日常步骤。

---

## 六、删除本地存储答案

> **本组只删本地缓存，不碰平台。** 没有二次确认、全删无分项。

### C6.1 正常删除

**背景**：这个按钮把本地的教师答案缓存和**全部**学生答案缓存一次删光。**它不加二次确认，点下去就删。**

**前置条件**：本地确实有缓存（先做 `C3.1`、`C4.1`）。

**操作步骤**
1. 点「删除本地存储答案」。
2. 注意有没有弹窗。
3. 看日志。

**期望结果**
- **不弹任何确认框**（这是 ADR 要求）。
- 日志出现一条完成提示，大意是「本地答案缓存已删除」。
- **平台上数据没有任何变化**（可刷新平台 T 型账页确认）。
- 日志**不会**分段列出「删了哪几份」（ADR 要求全删无分项）。

**失败时怎么判断**
- 弹出二次确认 → 与 ADR 不符，记录。
- 删除后平台上的行变少了 → **严重**，说明按钮接线错了（删到了平台），立即停止测试。
- 日志逐项列出「教师答案 1 份 + 学生答案 3 份」→ 记录（实装与 ADR 描述不符）。

> **判断要点：平台上必须一点没变。** 这是本组唯一真正重要的判据。

---

### C6.2 删除后教师答案必须重新抓

**背景**：删除之后，缓存就没了，下一次点获取按钮必须真的联网抓。

**前置条件**：`C6.1` 刚执行完。

**操作步骤**
1. 点「获取教师答案并写入 T 型账」。
2. 计时，看它是不是又慢下来了。

**期望结果**
- 耗时回到第一次的量级（分钟级），日志从抓取阶段重新数到 103 张。
- 写入正常完成。

**失败时怎么判断**
- 删了之后仍然是秒级进入归集 → 缓存没删掉，记录。

---

### C6.3 删除后学生答案必须重新抓、且不影响教师答案的删除范围

**背景**：删除是全删，所以这一步反过来验证「删完之后两份都得重抓」。

**前置条件**：本地同时有教师缓存与学生缓存。

**操作步骤**
1. 点「删除本地存储答案」。
2. 点「获取教师答案并写入 T 型账」，计时。
3. 点「获取学生答案并写入 T 型账」，计时。

**期望结果**
- 两次都从抓取阶段重新开始（各自慢一次）。

**失败时怎么判断**
- 其中一次仍是秒级 → 说明那一份没被删掉，记录是哪一份。

---

### C6.4 本来就没有缓存时点删除

**背景**：幂等动作，不该报错。

**前置条件**：刚执行过 `C6.1`（本地已无缓存），或全新安装。

**操作步骤**
1. 点「删除本地存储答案」。

**期望结果**
- 不弹确认框、不报错，日志给出「已删除 / 无可删除」一类中性提示。
- 后续操作不受影响。

**失败时怎么判断**
- 报红色错误 → 记录（属体验问题，不阻塞）。

---

## 七、停止与中断

### C7.1 抓取期间按「停止」

**背景**：抓 103 张凭证要几分钟，用户会想中途放弃。

**前置条件**：本地没有教师答案缓存（这样才会真的抓取）；已进入实训企业。

**操作步骤**
1. 点「获取教师答案并写入 T 型账」。
2. 等日志开始逐张报进度后，点「停止」。

**期望结果**
- 立刻出现一条提示：`⏹ 已请求停止，正在中断（当前正在提交的那一行会写完，其后不再写）`（句子按实装，关键是「已请求停止」+「其后不再写」）。
- 抓取停止，**不进入写入阶段**。
- 平台上没有任何变化。
- 面板按钮恢复：其它按钮变亮，「停止」变灰。

**失败时怎么判断**
- 按了停止但日志继续抓完 103 张 → 记录。
- 按了停止却仍进入写入 → **严重**。

---

### C7.2 写入期间按「停止」（改平台、不可恢复）

**背景**：这是最需要看清的一条。停止**不会**回滚已经写进平台的行，也不会打断「正在提交的那一行」。

**前置条件**：教师答案已有缓存（跳过抓取阶段，直接进写入）；平台上相关科目为空；科目数较多。

**操作步骤**
1. 点「获取教师答案并写入 T 型账」。
2. 等日志出现若干个 `[N/45]` 之后，点「停止」。
3. 读日志最后几行。
4. 等 5 秒，再翻日志。
5. 到平台上核对：按日志报出的「写入 M 个科目」，确认平台上正好有这 M 个科目的数据。

**期望结果**
- 出现 `⏹ 已中断：写入 M 个科目（未完成全部 45 个）。` 一类提示。
- **正在提交的那一行会写完**（该科目可能只写了一半），**其后不再写任何科目**。
- 日志停止增长，5 秒后再看还是那几行。
- 平台上正好有 M 个科目被写入（第 M+1 个及之后完全没动）。
- 「停止」按钮变灰，其它按钮变亮。

**失败时怎么判断**
- 停止后日志继续往下写科目 → 记录。
- 停止后**正在提交的那一行被截断**，平台上留下半行数据 → 记录（与 ADR 的描述不同）。
- 停止后所有按钮都变灰、面板卡死 → 记录。

---

### C7.3 写入中途停止后是否「该科目只写一半」

**背景**：ADR 的措辞是「正在提交的那行会写完，其后不再写」。注意它说的是**行**，不是科目。所以停止时正在处理的科目**允许**是残缺的。

**前置条件**：`C7.2` 刚执行完。

**操作步骤**
1. 找到停止时日志最后正在处理的那个科目编码。
2. 在平台上打开它的 T 型账页。
3. 看行数，与日志里它已经报出的行数比较。

**期望结果**
- 该科目行数 = 该科目在停止前已成功提交的行数（可能少于计划行数，这是允许的）。
- 该科目**没有**出现读回对账行（`✅ … 读回 …`），因为它没跑完。

**失败时怎么判断**
- 该科目行数是计划行数（即它其实跑完了但没报读回）→ 属实现细节，记录即可。
- 该科目行数为 0 且日志说它已经写了若干行 → 记录。

---

### C7.4 停止后能否继续/重跑

**背景**：停止之后面板必须能重新接受操作，否则一轮测试就废了。

**前置条件**：`C7.2` 刚执行完。

**操作步骤**
1. 点「清空 T 型账」→ 确认（把刚才写一半的残留清干净）。
2. 再点「获取教师答案并写入 T 型账」，完整跑一次。

**期望结果**
- 两个动作都能正常发起，日志照常滚动。
- 第二次跑不再出现停止提示，完整跑完。

**失败时怎么判断**
- 停止后按钮一直是灰的，点不动 → 记录（需要刷新页面才能恢复也算记录）。
- 第二次跑在同一个位置又自己停了 → 记录。

---

## 八、边界与异常

### C8.1 年月填错

**背景**：平台对 T 型账查询不给对错反馈，填错期间会「查得到但是空的」或者「查得到别人的期间」。v3 取消演练模式后，填错的后果直接落到平台上。

**前置条件**：本地有教师答案缓存（跳过抓取，快速进写入）；平台上相关科目为空。

**操作步骤**
1. 把年份改成 `2021`、月份改成 `7`（一个明显不对的期间）。
2. 点「获取教师答案并写入 T 型账」。
3. 观察日志与平台。

**期望结果**
- 脚本照常往该年月写入（不报错、不拦）。
- 平台上**另一个期间**出现了数据。
- 日志里的「期间」行显示的是 `2021 年 7 月`。

**失败时怎么判断**
- 日志里没有「期间」这一行 → 记录（用户无从确认写到了哪个期间）。
- 写进了 `2020 年 1 月` 而不是填的期间 → **严重**，记录。

> 这一条不是「找 bug」，是**确认你不能指望脚本帮你拦错**。

---

### C8.2 面板被平台重渲染冲掉

**背景**：平台的页面是整页提交式渲染。面板挂在内容框架里，框架被重渲染时面板可能消失。

**前置条件**：已打开 T 型账页，面板可见。

**操作步骤**
1. 在平台上手工操作一次会触发整页提交的动作（例如在 T 型账页点平台自己的「查询」按钮）。
2. 观察面板。

**期望结果**
- 面板重新出现（或保持）。
- 若面板消失，切换一次左侧菜单再回到 T 型账，面板应恢复，日志回到初始状态。

**失败时怎么判断**
- 面板消失后任何操作都唤不回来，必须刷新整个浏览器页面 → 记录。
- 写入过程中面板消失、日志停止增长 → **这一轮写入可能已经中断**，到平台上核对实际写入情况，记录该现象。

---

### C8.3 未审核凭证不构成闸门

**背景**：网页手册说「审核无误的记账凭证才能登记账簿」，但平台实际不拦（T 型账页里根本没有「审核」这个校验）。ADR 决定：**未审核只在日志报出，不阻止写入**。

**前置条件**：平台上存在「未审核」的凭证。

**操作步骤**
1. 点「获取教师答案并写入 T 型账」（或使用已有缓存）。

**期望结果**
- 日志里出现一条报出未审核凭证的提示，列出凭证号（形如「记61」「记62」）。
- **脚本继续写入**，不因为未审核而停手。
- 未审核的那些凭证如果本身借贷平衡，它们的分录**会**被写进 T 型账。

**失败时怎么判断**
- 脚本因为「有未审核凭证」直接停手 → **与 ADR 直接冲突**，记录。
- 日志完全没提未审核凭证 → 记录（ADR 要求报出）。

---

### C8.4 连点写入按钮

**背景**：v3 没有演练模式，误点就直接写。连点两次是最常见的误操作。

**前置条件**：平台上相关科目为空。

**操作步骤**
1. 快速点两下「获取教师答案并写入 T 型账」。

**期望结果**
- 第二次点击无效（按钮在运行时变灰）。
- 平台上写入的行数**不是**计划的 2 倍。

**失败时怎么判断**
- 平台上行数翻倍 → **严重**，判据失效或按钮未互锁，立即停止测试。
- 日志出现两遍完整的写入序列 → 记录。

---

### C8.5 缓存体积与写入耗时

**背景**：缓存量级约 250 KB（103 张凭证 / 417 条分录），存在浏览器本地存储里。ADR 说这个体积「可行」，但真实写入耗时需要真机确认。

**前置条件**：全新安装、本地无缓存。

**操作步骤**
1. 点「获取教师答案并写入 T 型账」，等它完整跑完（这一步会写缓存）。
2. 留意跑完之后有没有报错或卡顿。
3. 立刻点「获取教师答案并写入 T 型账」第二次（命中缓存），看归集阶段是否马上开始。

**期望结果**
- 缓存写入没有报错。
- 第二次命中缓存，很快进入归集。

**失败时怎么判断**
- 出现本地存储相关的报错（例如配额超限）→ **记录，这是 ADR 明确点名要在真机确认的风险**。
- 缓存写入是静默失败（不报错但第二次仍要重新抓）→ 见 `C5.1`。

---

## 九、已知不覆盖 / 需要人工判断

以下是本清单**做不到**的事，以及需要你自己拿主意的地方。

### 9.1 本清单无法判定的

1. **缓存有没有命中，从日志上完全看不出来。** ADR 规定命中缓存要「完全静默，连『用本地缓存』都不说」。所以 `C5.1` 只能靠「耗时明显变短」来间接判断，`C5.5` 需要开开发者工具。**对不会开开发者工具的用户，缓存是否生效是一个黑盒。**
2. **清空的确认弹窗里没有科目数量预告**（ADR 明确要求），所以你点确认前**无法知道将要清掉多少个科目**。
3. **锁二不过（`C3.4`）很难人为构造**，整轮测试很可能一次都触发不到。没触发到 ≠ 已验证。
4. **锁三在正常操作顺序下大概率显示「未执行」**：第一次跑时本地还没有学生答案缓存（见 `C3.1`）。所以「锁三一致」这个结果通常要等**先写教师、再写学生**这一套顺序跑下来才可能看到。若你的操作顺序相反，永远看不到锁三有结果。
5. **没有单科目小批量试写手段。** ADR 取消了单科目过滤器，真机验收只能全量跑：45 个科目写入 / 155 个科目扫描。想只试一个科目，本清单给不出办法。
6. **没有任何途径能在不碰平台的前提下验证「本次要写的计划是否正确」**（演练模式已删）。唯一的事后核对手段是「写完之后在平台上逐科目看」，而写错之后要修正又只能先清空。这是个闭环，清单绕不开。
7. **「155 个科目」这个数字无法在界面上核对。** 面板只给一个科目下拉，日志给分母。你没法在平台上数出 155 来对照。

### 9.2 需要你自己拿主意的

1. **测试前必须确认本批次数据可以随便清改。** 没有演练模式、没有单科目试写、平台无回滚。唯一的回滚是「清空后重跑」。
2. **共享电脑（机房）场景下缓存隔离是否够用。** 学生答案缓存存在浏览器本地，同一台机器换人登录时，若拿不到学号而回退到会话标识，缓存有串号风险。用共享机器测之前先想清楚这件事。
3. **教师答案缓存与学生答案缓存的批次校验不对称。** 教师答案缓存记了批次、不符时提示；学生答案缓存是否记批次，ADR 没有写。同一学生换批次后可能直接命中上一个批次的学生答案缓存，而且**日志完全静默**。请在 `C5.3` / `C5.4` 里重点观察，并据此决定要不要把「换批次时必须先删本地缓存」写成操作纪律。
4. **「清空 T 型账」与「删除本地存储答案」两个按钮只差两个字。** 一个删平台、一个只删本地，且都没有说明文字。执行前请逐字看清按钮文字。
5. **审核状态不做闸门是刻意的选择**（`C8.3`）。如果你的实训要求「未审核凭证不得登记账簿」，需要人工决定是否接受这个行为。
6. **写入所依赖的平台形态可能变化。** 判据是「凭证号前缀 + 金额 + 借贷方向」，**不比摘要**。所以摘要写错的凭证，脚本不会发现。

### 9.3 测试时请顺手记录的环境信息

1. 你是从校内直连进的，还是从校外网关进的（这会影响抓取行为）。
2. 你的实训批次编号（日志的「上下文」行里有）。
3. 教师答案的张数与分录数、归集出的科目数、借贷合计（第一次跑时记下来，用于与后续几次对比）。
4. 任何一条报红的行，**原样抄下整行文字**。
