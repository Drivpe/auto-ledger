# 7. T 型账路径串行化与响应完整性判据

日期：2026-10-13
状态：已接受
取代：ADR-0006 中「写路径 3 路并发，粒度是科目」一节（该节其余内容继续有效）

## 背景

round9 交付的版本（v3.1.0）按 ADR-0006 给写路径开了科目级并发。真机实测暴露出三类故障：

1. **残留恒为 1 行**：3 个科目报「N → 1 行」（N=4/13/34，与科目规模无关），残留行删不动。
2. **科目读到别的科目**：6411 报「清空前置 GET 失败或科目未切换」。
3. **汇总不闭合**：日志 `42 + 109 + 1 = 152 ≠ 155`，缺的 3 个正是「N → 1」的科目——汇总把「没清干净」静默吞掉了。

差分证据：旧版（全串行）用户实测「没问题」；引入并发后才出现问题。

## 决策

1. **T 型账路径一律串行**：新增 `CONFIG.tAccountConcurrency = 1`，用于四处并发点（写前普查、清空扫描、冲突清理、逐行写入）；删除 `writeConcurrency`。
2. **`clearAccount` 提交前断言每行 `TEMPid` 非空**（重取最多 2 次，仍缺则不提交）。这是独立于串行化的第二道防线。
3. **读路径统一校验科目归属**：`queryTStateChecked()` 比对响应里的 `accountID === code`。
4. **清空汇总五档闭合**：cleared / skipped / residual / unread / error，五档之和必须等于已处理科目数，任何一档非零都在日志点名。
5. **响应完整性判据**：`tStateIntegrity()` 区分「真 0 行」与「残缺成 0 行」（详见下节的分区口径）。

## 依据的强度分层（不要混着当同一件事）

- **① 真机差分（最硬）**：旧版全串行「没问题」，引入并发后出问题。用户一手观测。
- **② 离线 A/B（可复跑）**：同一 harness、只换脚本，旧脚本复现「N → 1」，新脚本全部机制被证伪。
  `V2T_QUICK=1 V2T_ROUNDS=2 node .scratch/voucher2t-taccount/verify/round10/harness/concurrency-race-harness.mjs`
- **③ 已证伪的解释**：曾把根因写成「服务端会话持『当前科目』，并发时删了别的科目的行集」。
  离线 harness 差分对该模型的严格「N → 1」命中率是 **0/10**，故**不得再引用**。
  可引用的表述是「**并发下读侧响应行集残缺**」。

## 响应完整性判据的分区口径（v3.3.0）

`tStateIntegrity()` 按「行集是否已解析出内容」分两区，严格度不同：

- **危险区 `rows = 0`**：无法从行集本身区分「真 0 行」与「截断成 0 行」，故要求旁证齐全——有 `_i` 模板行、有「本期发生额」合计行、有总账科目下拉项（拒绝平台降级页）、且合计两边都为空。任一不满足即判残缺并重取。
- **安全区 `rows > 0`**：行集已解析出来（有行就能删/写），不存在假成功；合计仅用于发现丢行，**单边容忍**——哪边非空比哪边，两边都空则放行。

单边容忍是**真机日志逼出来的**：1101/1231/1701/1702/2201/2203/2801/6401 这些正常科目的「本期发生额」合计就是空的（单边或双边）。早期版本写成「任一边为空即残缺」，把这 8 个正常科目全拦成失败、一行没删——误报面大于所修缺陷。

误报率实测（`verify/round10/d15/verify-fixtures-44.mjs`，44 份真机 query 夹具 + 2 份负例）：正常页误报 **0/42**，其中含 **7 份单边合计形态**（两个方向都有：只借方有值、只贷方有值）；2 份平台降级页被正确拒绝。

**已知盲区**（独立复务实测，不掩盖）：
1. 若某科目合计本来就为空，且响应又恰好被截断成 0 行，则该判据无法与真空账区分。
2. 多行科目被丢的那一行**金额为 0** 时，行金额和不变 ⇒ 单边比对漏报（实测「两行·尾行 0」
   与「两行·尾行仅借方 0」两种场景漏报）。单行载体（rows 归 0）不受影响 ——
   真机 6 个单行科目 1231/1701/1702/2201/2203/6411 全部被拦下。
   真机 49 份 `start=query` 样本中无此形态，当前零误报。

## 代价

串行化会拉长总时长：原本可重叠的网络等待变成逐个累加。按真机抓包实测（`verify/round9-perf-facts.md:68`，GET 均值 792ms），清空一轮仅只读 GET 就有 155 次，四路并发约 48 秒、串行约 194 秒。
凭证抓取（走别的 action，不碰 T 型账）保持 `readConcurrency = 4`，不受影响。

## 被取代的内容

ADR-0006 的「写路径 3 路并发，粒度是科目」一节由本 ADR 取代；ADR-0006 关于**凭证抓取并发**与**冲突科目交互式清空**的裁决继续有效。
