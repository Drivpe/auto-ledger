# 1. 以平台官方答案为 T 型账的数据源

日期：2026-09-29
状态：已接受（v2）

## 背景

v1 从「学生已录的记账凭证」抓数，经三重锁归集后登进 T 型账。这条路实测跑通（103 张 / 417 分录 / 45 科目 / 读回对账一致），但有一个隐含前提：**学生必须先把凭证录对**。换一个账号或任务，学生凭证若为空或录错，脚本产出就不可信。

实测发现平台在对比页里以 `SXID=0` 暴露「老师正确答案」（`do?action=zhsx_common&start=into_jzpzcx`），与学生版结构完全同构，且不随账号变化。并且实测确认：**本任务下答案与学生已录凭证逐笔完全一致**（103/103，归一化后差异为 0）。

## 决策

T 型账改以**平台官方答案**为数据源；同时保留学生凭证抓取，用于比对。

## 理由

- **可复用**：答案入口的 `SXID=0` 与账号无关，脱离「学生必须先录对」的前提。
- **零回归**：本任务下两者内容等价，切换不改动现有产出。
- **零成本复用**：字段名、单位、「空 form」怪癖全部同构，解析器可直接复用。
- **可验证**：答案成为**外部**权威参照，使锁三从「自证」变为「外部验证」。

## 代价

- 依赖平台保留答案入口。若教师端关闭该入口，需回落到学生凭证（保留该路径作为降级）。
- 答案列表页属性用 `&quot;` 转义，与学生版不同，解析需加实体解码。

## 备选方案与否决理由

- **只用学生凭证**：无法复用，且学生录错时静默产出错误 T 型账。
- **只抓答案不比对**：放弃了唯一的外部验证手段。
