# 4. 面板交互 v3：四按钮 + 本地答案缓存，取消演练模式

日期：2026-10-03
状态：已接受（实施待下轮）

## 背景

round5 交付的脚本面板存在三个问题，用户在实测后提出：

1. **演练模式没必要**。它对「首次全量运行前先看一眼计划」有意义，但代价是每次操作要跑两遍（先演练、再真跑），而演练本身也要逐个 GET 全部科目，耗时与真跑同量级。
2. **年月那一栏名不副实**。原设计把默认值留空、在面板上放一段「必须手填、自动识别不存在」的长说明文字，用户认为这属于「必填 + 一长串文字说明」的糟糕形态——实训任务绝大多数就是 2020 年 1 月，应当直接给默认值。
3. **破坏性操作的说明文字过重**。面板上有一整块警示区讲 `delete_loop` 不可恢复，属于吓人的噪音。

同时，数据获取方式要改：教师答案与学生答案抓一次就**永久留在本地**，之后复用，而不是每次运行都重新联网抓（一轮抓取 103 张凭证要几分钟）。

## 决策

### 面板形态

面板只保留：**年月输入 + 四个功能按钮 + 一块日志区**。删除全部说明文字块（含年月长说明、破坏性操作警示区）、删除「演练模式」复选框、删除「先清空该科目再重写」「只清空，不重写」两个复选框。保留「停止」。

四个功能按钮（顺序即建议操作顺序）：

| 按钮 | 行为 |
|---|---|
| 清空 T 型账 | 扫全部总账科目，凡已有行的都清空（`delete_loop`） |
| 获取教师答案并写入 T 型账 | 抓教师答案（或读缓存）→ 归集 → 写入 |
| 获取学生答案并写入 T 型账 | 抓学生答案（或读缓存）→ 归集 → 写入 |
| 删除本地存储答案 | 只删本地缓存（教师答案 + 全部学生答案），不碰平台 |

年月默认值直接写死 `2020` / `1`。

### 本地缓存

- 缓存**原始凭证**（103 张全量分录），不缓存归集结果——归集规则日后改动时无需重抓。
- **教师答案统一一份**；缓存记下取数时的实训批次（`EntityID`），与当前批次不符时**仅在日志提示，不阻断**。
- **学生答案按学生隔离**：隔离键优先用学号，取不到时回退 `SXID`。
- 命中缓存时**静默复用**，日志不额外说明。
- 「删除本地存储答案」是全删，不做分项选择、不加二次确认。

### 清空 T 型账

- 范围是**全部 155 个总账科目**（T 型账页的科目下拉实测共 155 项），凡已有行的都清。
- **不依赖先抓到凭证**，不过三锁——清空是重置动作，凭证取不到时也应能用它把平台清干净。
- 保留**一次确认弹窗**，且**点下去就弹、不先扫描**（弹窗不预告将清空多少个科目）。

### 写入

- 平台已有行时：与计划**不匹配就跳过不写**，并在日志报出该科目；匹配则静默跳过。（沿用 D3 宽容口径：比凭证号前缀 + 金额 + 方向，不比摘要。）
- **写入前不弹确认**，只在日志列出科目数与行数。
- **取消**面板上的「先清空该科目再重写」选项。要重写就先点「清空 T 型账」。
- **取消** `CONFIG.onlyAccount` 单科目过滤器。
- 两个写入按钮**并存**，先写谁就以谁为准，另一个会被「不匹配就跳过」挡住。

### 其他

- 锁三（教师答案 vs 学生答案逐笔比对）改为**用本地缓存顺带比对**：写教师答案时若本地已有学生答案缓存就比一次，没有就标「未执行」，不阻断。
- **审核状态不构成闸门**：仅在日志报出哪几张凭证未审核，不阻止写入。
- 修正 `@version` 到与实现相符的版本号。
- 删除无使用点的死配置 `CONFIG.confirmBeforeWrite`。

## 理由

- **审核不设闸门有实证支撑**：平台 T 型账录入页内联 JS 中「审核」出现 0 次，唯一业务校验是「借贷至少一项有值」；学生侧凭证列表里「记61 报销差旅费 / 未审核」与相邻「已审核」行**同表混排**，而记61 确实已登进 T 型账（真机读回 `贷 2093.00`，见 `verify/raw/round5-http-write/EVIDENCE.txt`）。官方手册那句「只有审核无误的记账凭证才能作为登记账簿的依据」是**教学口径**，「未审核」在四份手册中 0 次出现。若脚本自行加闸门，会在平台并不阻拦的情况下把整轮写入拦掉。
- **岗位角色不需要切换**：门禁只作用于「填制记账凭证」「审核记账凭证」两个入口（`probe/dump-top.html:136/148` 带 `ope_role` + `showRole`），T 型账入口 `:200` 无这两个属性。
- **清空范围取 155 而非归集出的 45**：清空是重置，用户换批次或数据混乱时需要一个不依赖凭证正确性的干净起点。
- **缓存原始凭证而非归集结果**：250 KB 量级（103 张 / 417 分录），`GM_setValue` 可承载；存原始数据使归集规则变更不必重抓。
- **年月给默认值 2020/1**：实训任务绝大多数就是这个期间；写死在 `CONFIG` 与面板 `value` 上，改一处即可。

## 代价

- **取消演练模式后，误点写入按钮就直接改平台数据，且平台无事务无回滚**。缓解手段只剩：写入前日志列出科目数与行数、锁闸门、随时可用的「停止」。这是本决策最实质的代价。
- **清空范围扩到 155 个科目**后，一次误点的影响面远大于旧版（旧版要求 `onlyAccount` 限定单科目 + 手输科目码）。确认弹窗成了唯一防线，且它不预告将清空多少个科目。
- **删掉 `onlyAccount` 后失去单科目小批量试写手段**，真机验收只能全量跑（45 科目写入 / 155 科目扫描）。
- **教师答案的批次相关性无实测**：仓库内 `EntityID` 取值只有 `110`（另一处 `entityID=6e` 是正则压测的假想负例），因此「教师答案随批次变化」是**声明而非实测**。缓存只做「不符时提示」这一层防护，是基于这一未定状态的保守选择。
- **学生隔离键依赖展示性文本**：学号只能从顶层文档标题 `学生(<姓名>)(<学号>)企业(…)(110)SXID(…)` 或 top 框架链接参数里抠，平台无格式契约。取不到时回退 `SXID`，此时同一人换批次会另起一份学生缓存。
- **面板只留日志区**后，155 科目扫描与 103 张凭证抓取期间没有任何「预计还要多久」的提示，只能看日志滚动。
- 真实缓存体积需在真机上确认 `GM_setValue` 写入耗时；本次只按离线数据量级（约 250 KB）判断可行。

## 未决 / 下轮验证

- 缓存命中、四按钮接线、155 科目扫描这三类新行为**尚无自动检查覆盖**。
- 交付形态定为：下轮产出**一版脚本 + 一份手工测试清单**，由用户自行安装 Tampermonkey 手工测试（不驱动面板）。
