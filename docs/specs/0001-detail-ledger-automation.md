# 1. 登记明细账自动化（含登账后打勾）

日期：2026-10-13
状态：ready-for-agent
上游：`docs/adr/0001`–`0007`；对齐记录见 `.scratch/voucher2t-mxz/ALIGNMENT.md`（本地，未入库）

## Problem Statement

平台在 T 型账之后还有一整条**操作链条**：登记科目汇总表 → 登记明细账 → 登记日记账 → 登记总账 → 编制会计报表。既有脚本只打通了「登记 T 型账」这一环，出了 T 型账页就什么也做不了。

老师这次把**明细账的教师答案**放了出来，于是这一环的数据不再是「自己算」，而是「照抄」——但照抄并不省事，因为它是**纯手工的几百次点击**：进明细账环节 → 开设新账簿（选活页三栏式）→ 账簿启用确认 → 逐条建账页 → 进每个账页，按期初余额表和记账凭证一行行填日期、凭证字、号数、摘要、借方、贷方、方向、余额 → 画月结线 → 再填一次同日期填本年累计 → 存。全部填完还有第二件事：回到记账凭证列表，对每张凭证点「查阅凭证」，把该科目在凭证里的那一行**打勾**并保存，否则平台上该凭证的登账情况一直停在 `/4`。

三处具体代价：

其一，**规模**。应登 **173 个账页**，分布在 **55 本账簿**里；账页内容共 **417 行**逐笔分录；加上 173 次建账页、173 组月结/年结线、以及覆盖面到 103 张凭证的打勾动作。单次全量手工操作以小时计，且几乎不可能一次做对。

其二，**手工抄必然错**。账页上的凭证号必须用**平台侧真实凭证号**。本项目此前由凭证归集出来的那份数据，凭证号是按列表序号重排的（`记i+1`），与平台明细账里的编号差一位（科目 1001 末笔：正确答案是 `记62`，归集结果是 `记63`）。照抄模式下这个差异会让**打勾定位不到行**——勾的是「某科目在某凭证里的行」，凭证号错一位就勾错。所以数据必须取自教师答案本身，而不是算出来的。

其三，**换人换批次就重来**。同一份脚本要在别的学生账号、别的实训批次上也能跑。而教师答案未必对所有账号开放；账号一旦取不到答案，这一环就整块瘫掉。

要做的是：把这条链条的第二环（明细账）也自动化，并且**在教师答案取不到时仍有可用的兜底数据**，让人只需点一次、看一眼进度、随时能停。

## Solution

在**既有油猴脚本**里加一个明细账模块（不新开脚本：凭证抓取、上下文解析、HTTP 层、缓存、日志这些最重的地基两边完全共享，另起一份必然分叉）。跑起来是这样：

进明细账环节，面板上**明细账**有自己独立的一组操作，与 T 型账、日记账等并列，互不混淆。点「登记明细账」，脚本自己完成整条链：取教师答案（**实时接口优先，取不到就落到仓库内置的兜底快照**）→ 按一级科目开出账簿 → 逐个建账页 → 把该账页的六类行照答案原样抄进去（含期初、逐笔、本月合计、月结线、本年累计、年结线）→ 抄完一个科目，立刻对这个科目涉及的凭证行打勾并保存。全程串行、有进度、可中断。

写入之前先对平台做一次**写前普查**：平台已有行且与计划不符的科目会被列出来让人决定，不会闷头覆盖。另有一个**独立的重置入口**负责把平台上的明细账清干净——它与登记是两个按钮，因为它不依赖答案是否取得到。

面板只认**教师答案**。「学生答案」在明细账这条链路上没有入口，界面上也不出现这个词。

## User Stories

1. 作为做过一次手工登明细账的学生，我想点一个按钮就把整环登完，这样我不必再花几个小时逐行点击。
2. 作为学生，我想让脚本自己开设账簿和账页，这样我不需要手工重复 173 次「建账页 + 提交修改」。
3. 作为学生，我想让脚本只开**活页三栏式**账簿，这样建出来的账与我该交的那本一致。
4. 作为学生，我想让脚本按**一个一级科目一本账簿**组织，这样账簿结构和会计口径对得上，也便于我事后按科目核对。
5. 作为学生，我想让只有**有期初余额或本期有发生额**的科目才建账页，这样 133 个两头都空的科目不会凭空多出一堆空账页。
6. 作为学生，我想让脚本把每个账页的名称设成科目名，这样我在账簿列表里能一眼认出是哪一页。
7. 作为学生，我想让期初余额照答案的「年初 / 上年结转」原样落进去，这样我不必自己对期初表。
8. 作为学生，我想让逐笔分录照答案原样落进去（日期、凭证字、号数、摘要、借、贷、方向、余额全抄），这样账页内容与老师答案逐字一致。
9. 作为学生，我想让凭证号取自教师答案而不是重算，这样最后一笔不会因为重排而错位。
10. 作为学生，我想让摘要也照答案抄，这样我不必另找摘要来源。
11. 作为学生，我想让余额列照答案填而不是留给平台算，这样平台上显示的余额就是老师那份。
12. 作为学生，我想让「本月合计」按答案的金额落进去，这样月汇行与我手工做的一致。
13. 作为学生，我想让月结线和年结线也自动画出来，这样账页上那两条红线不必我手点。
14. 作为学生，我想让脚本在画结线前先把该行的月、日填好，这样不会被平台以「"月"输入不能为空」拒绝。
15. 作为学生，我想在写完一个科目的账页后，脚本立刻把该科目相关的凭证行打勾，这样我不必切换回凭证列表逐张翻。
16. 作为学生，我想让打勾勾到**正确的行**（该科目在该凭证里的那一行），而不是整张凭证，这样登账情况显示的行数与实际相符。
17. 作为学生，我想让打勾用平台侧真实凭证号定位，这样不会勾错凭证。
18. 作为学生，我想让打勾保存走平台自己的保存路径，这样结果能被平台的「登账情况」列反映出来。
19. 作为学生，我想在凭证列表的「登账情况」列上看到勾选进度从 `/4` 变成 `1/4`，这样我能确认脚本的动作真的生效了。
20. 作为学生，我想让打勾的范围与登账范围一致——登了明细账的科目才打勾，这样不会出现多勾或漏勾。
21. 作为学生，我想让打勾是可重复执行的（同一状态重复保存不产生变化），这样中途停过再跑不会弄脏数据。
22. 作为学生，我想让整轮操作有进度显示（当前第几本账簿、第几个账页、第几行），这样长时间运行期间我知道它在动。
23. 作为学生，我想在运行中随时点「停止」，这样发现不对可以立刻收手。
24. 作为学生，我想在停止后知道平台上已经写进去了多少、还差多少，这样我能判断是接着跑还是重来。
25. 作为学生，我想在正式写入之前就拿到一份完整的冲突清单，这样不必「写到一个才发现一个」。
26. 作为学生，我想让平台已有行但与计划不符的科目**停下来问我**，而不是被静默覆盖。
27. 作为学生，我想能在对话框里选择「跳过它们」「清掉再写」或「停止」，这样处理方式由我定。
28. 作为学生，我想让不属于本轮计划的科目只被报出来、不被改动，这样别的批次留下的数据不会被误伤。
29. 作为学生，我想让查询失败的科目被单独报出并本轮跳过，这样我不会因为「以为是空的」而把两批数据叠在一起。
30. 作为学生，我想让「平台已经等于计划」的科目被静默跳过，这样重跑不会翻倍写入。
31. 作为学生，我想有一个独立于登记之外的**清除**入口，这样即使教师答案取不到、凭证也抓不到，我也能把平台清干净重来。
32. 作为学生，我想让清除有明确的危险提示与一次确认，这样我不会手滑清掉不该清的。
33. 作为学生，我想让清除只影响明细账，不碰 T 型账数据，这样两环互不牵连。
34. 作为学生，我想在换到别的学生账号时脚本仍能跑，这样我能帮同学做。
35. 作为学生，我想在当前账号的教师答案**尚未开放**时，脚本自动使用仓库内置的兜底快照，这样我不必等老师开权限。
36. 作为学生，我想在面板上看到当前数据源是「实时」还是「仓库快照」，这样我知道这份数据是从哪来的。
37. 作为学生，我想让兜底快照的来源和抓取时间可查，这样我能判断它是否还适用于我这个批次。
38. 作为学生，我想让数据源状态可以在面板上手动切换对比，这样我能确认两种状态的差异。
39. 作为学生，我想让面板对每个环节（T型账 / 明细账 / 日记账 / 科目汇总表 / 总账 / 会计报表）分开呈现，而不是全挤在一页，这样我不必在一个长列表里找当前环节。
40. 作为学生，我想让尚未接入的环节明确标出来，这样我不会去点一个还不工作的东西。
41. 作为学生，我想让面板支持深色模式，这样晚上做也不会刺眼。
42. 作为学生，我想让面板收起时尽量不显眼，这样它不会挡住平台页面。
43. 作为学生，我想让面板在一屏内说清关键状态，不要成段的说明文字，这样我扫一眼就能走。
44. 作为同学，我想让脚本装在浏览器里就能用（不改平台、不装环境、不用开发者模式），这样门槛低到同学能自己装。
45. 作为同学，我想让脚本复用我已经登录好的会话，这样我不必把账号密码填进脚本。
46. 作为维护者，我想让明细账模块与 T 型账模块共用同一套取数、缓存、HTTP 与日志设施，这样同类修复不会分叉。
47. 作为维护者，我想让写入前的计划生成与表单构造是可在离线复跑的，这样我能不连平台就证明「计划正确」和「拒绝逻辑正确」。
48. 作为维护者，我想让平台页面的解析有可回归的夹具，这样平台改版时我能立刻看出是哪一处解析塌了。
49. 作为维护者，我想让她沿用的 ADR 决策被显式引用而不是被默默改写，这样后来的人知道为什么是这样。
50. 作为维护者，我想让仓库名与脚本名反映「账簿自动登记」这个真实范围，而不是停留在只覆盖 T 型账的旧名。

## Implementation Decisions

### 范围与口径

- **本轮只做明细账这一环**（外加登账后的打勾）。日记账、科目汇总表、总账、会计报表只保留入口占位，不实现抽取器。
- **账簿类别只做 `(活页)三栏式明细账`**（平台该下拉的 value = `5`）。`数量金额式`（`6`）与`多栏式`（`7`）本轮不做。`(订本)明细账`（`3`）只存在于平台 HTML 注释里，DOM 枚举不到，不可选，忽略。
- **登账依据是照抄教师答案，不做凭证归集计算。** 这是本轮最重的口径变更：既有「三重锁」不再作为明细账的登账依据。修订后的**三重锁**只继续服务 T 型账那一环；明细账侧的校验改为「照抄过程自身可信 + 抄完读回核对行数」。
- **学生答案在明细账这环被整体弃用。** 即「统一以教师答案为准」。既有 T 型账面板上的「学生答案」入口按用户指令一并移除。
- **重跑口径是「先清空、再重登」。** 不设计增量修补。

### 规模与集合

- 应登账页 **173 个**，账簿 **55 本**（按一级科目），账页逐笔行 **417 行**。
- 账页集合口径 = 「有期初余额」∪「本期凭证触及」= 97 ∪ 150 − 74 = 173。这条口径已由两条独立路径同数验证（教师答案的非空科目数，恰为 173）。
- 平台对 306 个科目**都**会返回账页（连无余额无发生额的也有结构行）。按手册口径这类可以不建账，故 133 个空科目跳过。
- 打勾覆盖面至多 103 张凭证。

### 数据源与兜底快照

- 教师答案的取数入口是平台的「明细账正确答案」页，用 `SXID=0` 标识教师答案——与 T 型账教师答案**同源机制**。
- 取数走**按科目逐次查询**（306 个科目，实测约 0.7 秒/科目，全量约 212 秒）。支持断点续抓。
- **仓库内置兜底快照**：当当前学生账号的教师答案未开放时，脚本使用随仓库分发的明细账教师答案快照，使这一环不依赖老师的开放动作。快照自带 schema 标识（`auto-ledger/teacher-answer-snapshot@1`）、抓取时间与覆盖统计；**必须逐字节不含学号、姓名、密码、会话标识**。
- 快照与实时答案**结构同构**，消费代码不分叉：同一套解析器吃两种来源。
- 面板必须显示当前数据源（实时 / 仓库快照），并提供一个可点的状态开关以便对比两态。
- 兜底快照**不是**「学生答案」，两者的术语不能混用。

### 行模型（照抄的落点）

账页的六类行序固定：`年初 → 逐笔* → 月汇 → 月结线 → 年累 → 年结线`。**每个有内容的科目六类行齐备**（实测 173 个非空科目各 5 类结构行）。

| 行类 | 凭证种类 | 行类标识 | 摘要（固定） |
|---|---|---|---|
| 承前页 | `月初` | `0` | 承前页 |
| 上年结转 | `年初` | `1` | 上年结转 |
| 逐笔分录 | `记` / `收` / `付` / `汇` | `2` | 取答案自带摘要 |
| 本月合计 | `月汇` | `6` | 本月合计 |
| 月结线 | `--` | `8` | `------------` |
| 本年累计 | `年累` | `7` | 本年累计 |
| 年结线 | `==` | `9` | `=============` |
| 结转下年 | `年结` | `-1` | 结转下年 |

- **答案自带逐笔摘要**（150 个有逐笔行的科目全部自带非空摘要，150/150），照抄不需另找摘要来源。
- **金额单位是「分」**。账页上 `balance=732800` 即 7328.00 元；凭证记1 借方 232 元写入账页是 `debit=23200`。构造请求体时一切金额按分。
- 行方向字段 `in_debit_lend`：`0` = 平，`1` = 借，`-1` = 贷。**贷方字段名是 `lend`，不是 `credit`。**
- 月结线**不是纯样式**，是平台插入的**真实数据行**（行类 `8`），年结线同理（行类 `9`）。**画结线前必须先填该行的月与日**，否则平台以「"月"输入不能为空」拒绝。
- 已存行与待填行是**两种字段形态**：已存行用无后缀名，待填行用 `_i` 后缀（且待填槽位恒为一组）。因此**每次整页提交后必须重新解析页面状态**，不能靠前端记住。

### 平台契约（三个写接口 + 打勾保存）

全部为 `POST application/x-www-form-urlencoded`，通过脚本既有的 HTTP 层发出（不注入、不导航）。

| 动作 | 接口 | 关键参数 |
|---|---|---|
| 开账簿 | 账簿开设接口 | 提交段落标识改为 `new_zb_insert_1rec` |
| 建账页 | 账簿开设接口 | 提交段落标识改为 `insert_zy_1rec`；**账页名称必须显式提交，平台不自动取科目名** |
| 录行 / 画结线 | 账页接口 | 提交段落标识 `insert_1rec` |
| 修改提交 | 账页接口 | 提交段落标识 `update_loop` |
| 删账簿 | 账簿开设接口 | 提交段落标识 `zb_delete`，并回传 `CHECK_CONFIRM=<账簿ID>` |
| 打勾保存 | 记账凭证接口 | 提交段落标识 `dzqkjl`，提交目标为 `saveWin` |

- 平台「账簿启用确认」**不是独立接口**，就是同一张表单独提交并改写提交段落标识。
- 开账簿表单字段：账簿类别（下拉，本轮固定选三栏式）、账簿名称、账簿编号、对应科目（下拉）、启用日期。
- 账页已存行字段：月、日、凭证种类、凭证号、摘要、借方、贷方、方向、余额、删除确认、行标识、内部标记若干。待填行是同名字段加 `_i` 后缀，另有行类与行号字段。
- **打勾控件命名是「行号 + 后缀」形态**（第 N 行对应固定的一个控件名），第 N 行对应科目可从同前缀的两个字段读到一级码与明细码。行号从 1 起，含空行槽位。
- 平台可能对某些行**自算余额**，但本轮决定照答案填，不依赖平台自算。

### 打勾（新增需求）

- **打勾的位置在记账凭证里，不在明细账页上。** 明细账账页 HTML 全文不含「记账」二字。
- 打勾的**目标单位是「某科目在某凭证里的那一行」**，不是凭证本身，也不是科目。同一凭证若涉及多个科目，各勾各的。
- 打勾**必须用平台侧真实凭证号**定位（这正是照抄模式必要性的直接证据：归集口径的 `记63` 在平台上不存在）。
- **可观测效果**是记账凭证列表「登账情况」列由 `/4` 变为 `1/4`。这是平台侧的显示，也是打勾的**天然幂等判据**。
- 打勾保存**幂等**：同一状态重复保存不产生变化。
- 打勾保存会伴随一条无害的平台自身 JS 报错（刷新调用失败），**不得据此判定保存失败**；判定以保存成功提示与列表显示为准。
- **打勾范围与登账范围一致**，**时机是逐科目**：写完一个科目的账页，立即对该科目涉及的凭证行打勾。

### 幂等与写前普查

- 沿用既有的**写前普查**形态：写入前对平台做只读普查，把结果分成五档——无行（直接写）、逐行一致（**幂等跳过**）、不匹配（**停下问人**）、查询失败（本轮跳过并单独报出）、计划外（只报不动）。
- 幂等判据沿用既有口径：**凭证号前缀 + 金额 + 借/贷方向，不含摘要**。
- 术语沿用 **冲突科目 / 计划外科目 / 未知科目** 三个既有定义，不新造同义词。
- 「未知科目」与「平台是空的」是两回事，**绝不能并入无行直接写入**（那会叠写）。

### 清除

- 清除是**独立入口**，与登记并列，且**不依赖教师答案是否取得到、不过任何校验闸门**。
- 清除范围是明细账侧的全部账页（含账簿与账页自身），**不触碰 T 型账数据**。
- 防线是一次明确的危险确认。面板上它必须是**危险语义**的按钮（红色描边 / 警示图标 + 明确的不可撤销文案），不能与正向操作长得一样。
- 用户已明确要求：既有脚本里那些「先清空再写」「只清空不写」之类**每次运行都要预先决定的开关**不再回来；清除是一个用户主动点的动作。

### 并发与节流

- **明细账路径默认严格串行。** 既有 ADR-0007 的串行依据只覆盖 T 型账页；明细账路径的并发**从未实测**。按本项目既定口径：**不得凭推测开并发**。串行是保守基线，不是测量结论。
- 只读的答案抓取沿用既有并发（凭证抓取的四路并发）。明细账侧请愿接口是否可并发，留作后续单独取证。
- 请求间隔沿用既有的节流值。

### 面板

- 面板从「一条长列表面板」改为**按环节分区**：T型账 / 明细账 / 日记账 / 科目汇总表 / 总账 / 会计报表 各自独立，未接入的环节明确标记。
- 一键收起，收起态走低调路线。
- 完整支持深色模式。
- 文案以「一屏说清状态」为准：不写说明段落、不写警示区块、金额不保留无意义的小数尾。
- 面板只呈现教师答案这一个数据源，界面上不出现「学生答案」字样。
- 面板的实现骨架（竖向导航 / 横向标签 / 悬浮下钻三选一）是一次**独立的视觉决策**，其选择不改变本 spec 中的任何行为契约。

### 模块边界

在既有脚本内新增，复用既有设施而非另起一套：

- **复用**：HTTP 层（GET / POST）、只读并发池、上下文解析与跨框架定位、全部记账凭证抓取链、答案缓存、日志与进度设施、写前普查的形态与交互。
- **新建**：账页状态解析、账页请求体构造、明细账读回核对、账页列表解析与抓取、单账页登记、单账页清除、明细账普查、账簿与账页的创建、打勾的定位与保存。
- **改造**：面板宿主判定要收窄到真正的内容框架（否则面板挂错层）；既有冲突裁决对话框的元素标识与文案要参数化；表单提交函数的作用对象要提成参数。

### 顺序与中断语义

- 整轮顺序：取答案 → 普查 → 开账簿 → 建账页 → 抄行 → 画结线 → 打勾，逐科目推进。
- 因平台**无事务、无回滚**，中断后平台上会留下「已插入若干行、未做整体提交」的中间态。**允许该中间态存在，不做自动补偿**（自动补一发提交违背「停止后不再写」的语义，更危险）；但在日志中**明确报出**该科目的中间态，并把「清除」作为标准恢复路径。

### 前置验证闸门（开工第一步）

以下三条未闭合，**必须在写实现之前用最小代价实测闭合**，因为它们会直接改写实现方案：

1. **一本账簿能否容纳同一一级科目下的多个账页**（如 1002 下的 100201–100204）。这是「一个一级科目一本账簿」方案的**地基**，直接决定账簿数是否真的落在 55。
2. **账簿名称重复是否被平台拒绝**。55 本需要各自唯一命名。
3. **账页标识（平台内部 ID）从何而来**（服务端生成 / 按科目序）。已观测到「账簿 ID」与「账页 ID」是两个不同的值域，对应关系未确证。

另有两条不阻断但需登记：凭证里有 31/417 行的明细科目为空（照抄模式下影响变小，但打勾仍需决定勾哪一行）；年结线写入曾被平台以「上月未结账，不可输入下月记录」拒绝，一月任务是否需要年结线待确认。

## Testing Decisions

### 什么是好测试

**只测外部行为，不测实现细节。** 具体到本项目：测试断言的是「给定平台的这些页面响应，脚本向平台发出了哪些请求、请求体里是什么」，而**不是**「脚本内部调用了哪个函数」。理由很直接：平台是唯一的外部系统，脚本的全部价值体现在它与平台之间的请求序列上；内部函数名与分层是维护者随时可以改的自由，把它们写进断言只会让重构变成改测试。

对应地，**测试不得断言 DOM 内部结构**（哪个 `div` 套哪个 `div`），只断言「渲染出来的可见文字里有/没有某个词」这一层级——面板已经有既有验收脚本按这个粒度在跑。

### 唯一的测试缝（seam）

**缝在「平台会话边界」，即脚本的传输层端口。**

做法沿用仓库既有形态：把**脚本真身**装进一个隔离的脚本沙箱执行（不复制、不改写源码，只从原文里取真函数或在沙箱内替换传输层），**唯一被替换的是那一个发出 HTTP 请求的端口**，其余全部跑真代码。

选它的理由：

- 它是**最高**的可用缝——比任何单个函数都高，一次替换就能覆盖「取答案 → 规划 → 构造请求体 → 提交 → 读回」整条链的真实编排。
- 它**已经存在**且已在用：仓库里既有多个离线复跑脚本正是这个形态（把脚本装进沙箱、替换传输层、喂录制的平台页面夹具、断言行为），其中一个 harness 甚至把真实的整轮清空逻辑放进浏览器上下文跑。**本轮不新开第二个缝。**
- 它天然把网络也挡在外面：测试不连内网、不连 WebVPN，全部输入来自仓库内既有的实测夹具。

**不新增第二个缝的理由**：任何「为测试方便而抽出的纯函数层」都会与这条缝覆盖同一批逻辑，多出来的只是维护面。若某段逻辑在传输缝上不可断言（例如它只在真实浏览器布局下才成立），那是**放到验收脚本**的信号（见下），而不是再开一条缝。

### 哪些模块在这条缝上被测试

- **账页状态解析**：喂既有实测页面夹具（已存行 / 待填行 / 空账页 / 含结线行），断言解析出的行集与字段。
- **账页请求体构造**：断言金额以**分**为单位、贷方字段名、方向取值、各行的凭证种类与行类标识。
- **账簿与账页创建**：断言提交段落标识与必填字段（尤其账页名称被显式提交）。
- **幂等判据**：喂「平台已等于计划」「平台有行但不符」「平台查询失败」三种响应，断言分别产出「零写入」「停下问人」「本轮跳过」。
- **写前普查的五档分流**：断言冲突科目 / 计划外科目 / 未知科目被正确分档，且计划外与未知科目**不产生任何写请求**。
- **打勾定位**：喂实测的凭证页夹具与教师答案，断言勾选控件名与凭证号都取自平台侧真实编号；断言「已勾则重复保存不产生变化」。
- **错误处理**：喂平台的各类拒绝提示，断言脚本停在预期档位并报出可读原因。
- **兜底快照的数据契约**：断言仓库内置快照与实时答案**结构同构**、单位一致、行类齐备、且**不含学号/姓名/密码/会话标识**。这条是纯数据契约测试，与上面对同一缝的调用并列。

### 验收脚本（同一个缝，真浏览器侧）

面板与整链的端到端验收沿用仓库既有的验收脚本形态：在真浏览器里加载面板与夹具、逐变体 ×  明暗两主题截图并断言（挂载成功、零控制台错误、不出现「学生答案」字样、默认实时态、兜底态可达）。

### 既有测试先例（prior art）

- **离线形态回归**：仓库里既有的两个「只读、离线、不连内网」复跑脚本，把脚本真身装进沙箱并断言真函数返回值。
- **真身跑真逻辑的竞态 harness**：既有的并发 harness 把真脚本装进浏览器上下文、只替换传输层，跑真实的整轮清空逻辑，并用「注入可证伪机制 → 观察是否产出与真机同形的日志」的方式做因果判定。本轮的明细账测试直接沿用这套方法论。
- **面板验收脚本**：既有的面板验收脚本按「挂载 / 控制台零错误 / 禁止字样 / 状态可达」四条断言逐变体 × 两主题跑。

## Out of Scope

- **日记账、科目汇总表、总账、会计报表、纳税申报、报表分析**这几个环节。面板上只保留占位标记，不实现抽取器。
- **数量金额式明细账与多栏式明细账**。平台有这两个页签，本轮不碰。
- **学生答案**。在明细账这条链路上整体弃用，界面上不出现入口；既有 T 型账面板上的学生答案入口按用户指令一并移除。
- **凭证归集计算**。明细账不再由凭证算，改为照抄教师答案。既有归集逻辑继续服务 T 型账。
- **增量修补 / 断点续登**。重跑口径是「先清空、再重登」。
- **明细账路径的并发提速**。默认串行，并发可行性留作后续单独取证。
- **自动补写中间态**。停止后平台上的半成品不做自动补偿，只报告。
- **平台侧的任何改造**。脚本不修改平台代码、不注入页面脚本、不要求改平台配置。
- **T 型账那一环的行为变更**。除「移除学生答案入口」这一条用户明确要求的改动外，T 型账的既有行为不动。

## Further Notes

- **ADR 关系**：本 spec 与 ADR-0007（T 型账严格串行）不冲突——它约束的是 T 型账页，明细账侧本轮取同样的保守基线但不声称已测量。与本 spec 相关的既有决策集中在 ADR-0001（以教师答案为数据源）、ADR-0003（HTTP 写路径）、ADR-0004/0005（面板形态 v3 与实施裁决）。**ADR-0004/0005 中关于「学生答案入口」「演练模式」「四按钮形态」的条文，对本 spec 已被后者取代**——这需要在实现落地时补一条 ADR 显式记录取代关系，而不是默默改写旧 ADR。
- **术语**：本 spec 一律使用 `GLOSSARY.md` 的既有词汇（教师答案 / 学生答案 / 幂等判据 / 写前普查 / 冲突科目 / 计划外科目 / 未知科目 / 面板宿主 / 答案缓存 / 实训批次 / 操作链条 / 三重锁）。**账簿、账页、打勾、兜底快照**四个词目前不在术语表里，属于真实缺口，落地时应补进 `GLOSSARY.md`。
- **仓库更名**：仓库已从只覆盖 T 型账的旧名改为 `auto-ledger`，脚本的安装名同步改为「账簿自动登记」，以反映真实范围。旧地址由平台自动重定向。
- **本地工单目录**：`.scratch/` 被版本控制忽略（内含未脱敏的学号与姓名），因此本 spec 放在受版本控制的位置发布，不遵守 issue-tracker 文档里「spec 放 `.scratch/`」的默认约定。
- **待用户拍板的一项**：面板骨架三选一（竖向导航 / 横向标签 / 悬浮下钻）。三个原型都已按本轮要求改到位并验收通过，选定后再折进真实面板实现。
- **可能的后手**：平台有一个「自动建账簿」按钮。本轮决策是脚本自己逐个建账页（不依赖它），但若前置闸门证明它能把全部明细科目账页一次开全，可省掉本轮最大的工作量——值得在闸门阶段顺手一测。若可用，再决定是否改用它。
