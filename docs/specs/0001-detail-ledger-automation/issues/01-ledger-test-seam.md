# 01 — 明细账的唯一测试缝：脚本沙箱传输缝离线 harness

**What to build:** 后续每一张明细账工单都可断言「给定平台的这些页面响应，脚本向平台发出了哪些请求、请求体里是什么」——离线、不连内网、不连 WebVPN。把脚本真身装进隔离沙箱执行，唯一被替换的是那个发出 HTTP 请求的端口，其余全部跑真代码；喂仓库内既有的实测页面夹具，输出一条可读的请求序列断言。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] 沿用仓库既有的「脚本真身 + 只替换传输层」形态，不复制、不改写源码，不新开第二个缝
- [ ] 夹具取自仓库内既有的实测产物，测试过程零网络出口
- [ ] 能对一条「取答案 → 规划 → 构造请求体 → 提交 → 读回」的链子断言完整请求序列
- [ ] 断言粒度停在请求与响应上，不断言脚本内部函数名、不成断言 DOM 结构
- [ ] 一条命令可复跑，退出码区分「断言通过」与「断言失败」
- [ ] 至少用一条 T 型账链路的既有用例证明这个 harness 真能跑真代码（防止空壳 harness 伪装通过）

## Comments

spec `docs/specs/0001-detail-ledger-automation.md` 的 Testing Decisions 已定：缝在「平台会话边界」，即脚本的传输层端口；既有多个离线复跑脚本与该形态同源，本轮沿用而不新开。
