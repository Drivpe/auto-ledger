# 08 — 明细账写前普查与五档分流

**What to build:** 正式写入账页之前，脚本对平台做一次只读普查，并给出**完整的**处理清单，而不是「写到一个才发现一个」。五档分流落到明细账这条链路上；计划外科目的数据一个字节都不动。

**Blocked by:** 02, 05, 07

**Status:** ready-for-agent

- [ ] 逐科目只读普查平台账页当前状态，写入前即产出完整清单
- [ ] 五档分流：平台无行 → 直接写；平台已等于计划 → **静默跳过（零写入）**；有行但不匹配 → **停下问人**；查询失败 → 本轮跳过并单独报出；不属于本轮计划 → 只报出、不改动
- [ ] **幂等判据（用户已拍板）**：逐行对齐——凭证号前缀 + 金额 + 借/贷方向，**行数与行序都要对上**；对不上即判为冲突科目
- [ ] 「未知科目」绝不并入「无行直接写入」（那会叠写）；断言这档**不产生任何写请求**
- [ ] 冲突科目的三种处置可达：跳过它们 / 清掉再写 / 停止；处置结果进日志
- [ ] 术语沿用既有的冲突科目 / 计划外科目 / 未知科目，不新造同义词
- [ ] 断言：喂「平台已等于计划」「平台有行但不符」「平台查询失败」三种响应，分别产出零写入 / 停下问人 / 本轮跳过

## Comments

幂等判据由用户在本轮拆单时拍板为「逐行对齐（含行数与行序）」，取代 spec 中未定的空档；共用口径来自 `GLOSSARY.md` 的既有「幂等判据」条目。
