# 12 — 明细账清除入口

**What to build:** 一个独立于登记的按钮，把平台上的明细账清干净，让「先清空、再重登」这个重跑口径可执行。它的价值在于**不依赖任何前置条件**：教师答案取不到、凭证也抓不到的时候，它照样能用。

**Blocked by:** 06, 01, 02

**Status:** ready-for-agent

- [ ] 清除是**独立入口**，与登记并列，不依赖教师答案是否取得到，不过任何校验闸门
- [ ] 清除范围是明细账侧的全部账页（含账簿与账页自身）
- [ ] 断言清除过程**不触碰 T 型账数据**：跑完之后 T 型账侧零变化
- [ ] 删除走平台的删账簿提交段落并回传对应的确认字段；删完自愈复查一次
- [ ] 防线是一次明确的危险确认；面板上它必须是危险语义的按钮（红色描边 / 警示图标 + 不可撤销文案），不能与正向操作长得一样
- [ ] 消灭一切「每次运行都要预先决定的清空开关」：清除只由用户主动点触发，不在登记流程里附带
- [ ] 串行推进、有进度、可中断；中断后平台上留下什么被明确报出

## Comments

用户已明确要求：既有脚本里「先清空再写」「只清空不写」之类每次运行都要预先决定的开关不再回来。spec 的清除一节点名清除与登记是两个按钮。
