# 02 — 写前普查与冲突裁决的通用化

**What to build:** 写前普查的**五档分流**（无行直接写 / 逐行一致幂等跳过 / 不匹配停下问人 / 查询失败本轮跳过并单独报出 / 计划外只报不动）以及那个「清掉 / 跳过 / 停止」的裁决对话框，从「T 型账专用」变成可被明细账复用的通用形态。做完之后 T 型账那一环的行为逐字不变，明细账那一环的能力已经就位。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] 裁决对话框的元素标识与文案参数化，不再把 T 型账的字样写死在结构里
- [ ] 五档分流以「候选集合 + 逐科目比对函数」为输入，而不是内联在 T 型账流程里
- [ ] 术语沿用既有的「冲突科目 / 计划外科目 / 未知科目」，不新造同义词
- [ ] 「未知科目」与「平台是空的」在代码路径上确实分开，未知科目不产生任何写请求
- [ ] T 型账既有行为回归：既有验收脚本与离线复跑用例逐条通过、断言未放宽

## Comments

spec 的 Implementation Decisions「幂等与写前普查」要求沿用既有形态与既有术语，只做参数化，不顺带改动口径。
