# 13 — 打勾定位与保存

**What to build:** 每写完一个科目的账页，脚本立刻回到记账凭证，把「该科目在该凭证里的那一行」勾上并保存，使凭证列表「登账情况」列由 `/4` 变成 `1/4`。这一张补上手工流程里最容易被忘掉的那半件事。

**Blocked by:** 07, 09

**Status:** ready-for-agent

- [ ] 打勾的位置在**记账凭证**里，不在明细账页上（账页全文不含「记账」二字）
- [ ] 打勾的目标单位是**某科目在某凭证里的那一行**，不是凭证本身也不是科目；同一凭证涉及多个科目时各勾各的
- [ ] 定位**必须用平台侧真实凭证号**（`记62` 而非重排的 `记63`），断言勾选控件名与凭证号都取自平台侧真实编号
- [ ] 保存走平台自己的保存路径（提交段落标识 `dzqkjl`，提交目标 `saveWin`）
- [ ] 可观测效果：记账凭证列表「登账情况」列由 `/4` 变为 `1/4`
- [ ] **幂等**：断言已勾状态下重复保存不产生变化
- [ ] 保存伴随的无害平台 JS 报错**不得**被判定为保存失败；判定以保存成功提示与列表显示为准
- [ ] 打勾范围与登账范围**一致**：登了明细账的科目才打勾；登了的科目必须打勾
- [ ] 时机是**逐科目**：写完一个科目的账页立即打勾，而不是全部登完再回头翻
- [ ] 凭证里明细科目为空的行勾哪一行，按闸门登记结论处理

## Comments

打勾用真实凭证号定位，正是「照抄而非归集」这个口径变更必要性的直接证据：归集口径的 `记63` 在平台上不存在。
